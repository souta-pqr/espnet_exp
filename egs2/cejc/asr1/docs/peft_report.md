# PEFT（LoRA / Adapter）実験 報告書

発話区間末検出タスクにおいて、凍結した音声認識エンコーダを **PEFT（Parameter-Efficient Fine-Tuning）** で部分適応させ、タグ予測性能と音声認識性能（CER）のトレードオフを調査した記録。

- 対象コーパス: CEJC（日本語日常会話コーパス）
- 評価セット: eval 23,444 区間
- 作成日: 2026-07-24

> **⚠ Stage1 の前提について（2026-09-24 追記）**
> 本書の CER および Stage2 の全数値は、Stage1 = `20260713-pureasr`（**CER 23.3**、
> `block_size: 18`）を前提としている。その後 Stage1 を改善し
> `20260921-pureasr-blk42-sp`（**CER 20.7**、`block_size: 42`）を得た。
> **新しい Stage1 に乗り換える場合、`block_size` が変わるため本書の実験はすべて
> やり直しになる**（本書の数値と直接は比較できない）。→ `docs/stage1_asr_improvement.md`

## 1. 背景と目的

### 1.1 出発点となった知見

Stage2（エンコーダ凍結 ＋ Self-Attention ヘッド）の一連の実験で、以下が判明していた。

- 過去発話の与え方（N=0〜5、同一話者 / 複数話者）をどう変えても、**継続/完了の二値分離精度は 0.65 前後で頭打ち**。
- macro-F1 も 0.71〜0.72 の範囲でほとんど動かない。

この「壁」がどこに起因するかを切り分けるため、**エンコーダの表現そのものを適応させたらどうなるか**を検証する。ただしエンコーダを全面的に再学習すると、

1. 凍結された Decoder が期待する表現から外れ、**ASR（音声認識）が壊れる**、
2. 計算量が大きい、

という問題がある。そこで、元の重みを保ったまま少数のパラメータだけを追加学習する **PEFT** を用いる。

### 1.2 モデルの前提

| 項目 | 設定 |
|---|---|
| エンコーダ | Contextual Block Conformer（12 ブロック、output_size 256） |
| デコーダ | Transducer |
| ヘッド | Self-Attention 1 層 → MLP（現発話の最終フレーム位置を読み出す） |
| 損失 | `loss = loss_tag` のみ（ASR 損失は計算しない） |
| 初期化 | Stage1（純粋 ASR）の重みを `init_param` で読み込み |
| 凍結 | `freeze_param: frontend / normalize / encoder / decoder / joint_network / ctc` |

**重要な含意**: 損失がタグ損失のみであるため、学習中に ASR を保護する力は働かない。エンコーダを動かせるようにした瞬間、モデルは「タグ予測に有利ならエンコーダ出力をいくらでも書き換えてよい」状態になる。この性質が後述の Adapter の暴走（CER 46.7）の根本原因となった。

## 2. 実装

### 2.1 共通の課題: 凍結エンコーダに勾配を通す

既存の Stage2 モデルは、エンコーダを `@torch.no_grad()` かつ `.eval()` 固定で呼んでいた（ASR をビット単位で不変にするため）。PEFT ではエンコーダ内の追加パラメータに勾配を流す必要があるため、`tt_adapt` フラグを追加し、以下を切り替えるようにした（`espnet2/asr/espnet_model_turntaking_xfmr.py`）。

- `tt_adapt == "none"`（従来）: `no_grad` ＋ `detach` ＋ エンコーダ `.eval()`。ASR 完全不変。
- `tt_adapt != "none"`（PEFT）: エンコーダを **勾配ありで** 通す。base の重みは `freeze_param` で凍結済みなので、勾配が流れるのは追加パラメータのみ。BatchNorm の running 統計だけは `.eval()` に固定して不要なドリフトを防ぐ。

```python
def train(self, mode=True):
    super().train(mode)
    for m in (self.frontend, self.normalize, self.decoder, self.joint_network, self.ctc):
        if m is not None: m.eval()
    if self.tt_adapt == "none":
        self.encoder.eval()                    # 完全凍結
    else:
        for sub in self.encoder.modules():     # PEFT: BN だけ eval に固定
            if isinstance(sub, _BatchNorm): sub.eval()
```

### 2.2 LoRA の実装

ESPnet 組み込みの `create_lora_adapter`（`loralib` ベース）を利用した。`freeze_param` でエンコーダ全体を凍結した**後**に、各線形層を `lora.Linear` に置換する。置換時に事前学習済みの重みは新モジュールへコピーされ（`requires_grad=False` のまま）、新規に追加される低ランク行列 A, B のみが学習対象になる。

**式**: 重み行列 W に対し、`W' = W + (α/r)·B·A`（A: d×r, B: r×d, r ≪ d）。B を零初期化するため、学習開始時は補正 0 ＝ 元のモデルと完全同一挙動。

| ハイパーパラメータ | 値 |
|---|---|
| 適用先 target_modules | 各 Conformer ブロックの自己注意 `linear_q`, `linear_v` |
| rank r | 8 |
| alpha α | 8 |
| dropout | 0.05 |

- 設定ファイル: `myconf/train_asr_turntaking_xfmr_lora.yaml`（`use_adapter: true`, `adapter: lora`, `save_strategy: all`）
- 実行: `run_xfmr_lora.sh` / `run_exp_xfmr_lora_series.sh`

学習で得られた補正の大きさは **ΔW/W ≈ 0.85（中央値）** であり、元の重みと同オーダーに自然に収まっていた（W という基準が存在するため）。これが LoRA が壊れにくい理由である。

### 2.3 Adapter の実装（自前実装）

ESPnet 組み込みの Houlsby Adapter は **S3PRL フロントエンド専用**（`assert isinstance(model.frontend, S3prlFrontend)`）で、本構成（log-mel + Conformer）では使えないため、自前で実装した。

**挿入方式**: モジュールを差し替えるとパラメータ名が変わり Stage1 重みが読めなくなるため、**forward hook** で FFN の出力に補正を加算する方式を採用。これによりエンコーダのパラメータ名は不変に保たれ、Stage1 チェックポイントをそのまま読み込め、`freeze_param: encoder` も従来どおり機能する。

```python
class BottleneckAdapter(nn.Module):
    # down(d→r) → ReLU → up(r→d)。up は零初期化（初期は恒等）。
    def forward(self, x):
        out = self.up(self.act(self.down(x)))    # LayerNorm は入れない（後述）
        if self.max_ratio > 0:                   # 補正量の上限（後述）
            scale = clamp(self.max_ratio * ||x|| / (||out|| + eps), max=1.0)
            out = out * scale
        return out
```

**式**: ブロックの主 FFN 出力 h に対し、`h' = h + Adapter(h)`。up を零初期化するため学習開始時は恒等。

#### 実装上の3つの改善（試行錯誤の記録）

| 版 | 設計 | CER | 問題点 |
|---|---|---|---|
| v1 | 入力 LayerNorm あり / 24 箇所（主 FFN ＋ macaron FFN） | 46.7 | ASR 崩壊 |
| v2 | LayerNorm 廃止 / 12 箇所（主 FFN のみ） | 36.8 | 改善するが不十分 |
| **v3** | v2 ＋ **補正量の上限 max_ratio** | **可変（後述）** | 制御可能に |

- **入力 LayerNorm の廃止**: LN を入れると補正量が入力の大きさと無関係になり、活性が小さい領域で補正が支配する。LN なしなら補正は入力に比例し、LoRA と同じ性質になる。
- **挿入箇所の半減（24→12）**: macaron FFN はブロック先頭にあり、乱すと後続の self-attention・畳み込み全体が汚染される。層をまたいだ摂動の累積が CER 悪化の主因だった（実測で v1 は補正/FFN 出力比 中央値 0.54 だが 24 箇所ぶん累積、v2 は同 1.06 だが 12 箇所）。
- **補正量の上限 `max_ratio`**: 「補正の大きさ ≤ s × 入力の大きさ」となるよう各時刻で射影する。s が適応の強さを直接制御する「つまみ」になる。LoRA には W という基準があるが Adapter には無いため、この上限が無いと補正が青天井になる（制限なしのとき補正/FFN 比 中央値 1.06、最大 35.3 まで育ち CER 36.8）。

| ハイパーパラメータ | 値 |
|---|---|
| 挿入先 | 各 Conformer ブロックの主 FFN 出力（12 箇所） |
| ボトルネック次元 | 32 |
| 入力 LayerNorm | なし |
| 補正量の上限 s (max_ratio) | 0.4（下記の掃引で選定） |

- 設定ファイル: `myconf/train_asr_turntaking_xfmr_adapter.yaml`
- 実行: `run_xfmr_adapter.sh` / `run_exp_xfmr_adapter_series.sh` / 掃引: `run_exp_adapter_ratio_sweep.sh`

## 4. 考察

### 4.1 手法比較（最良条件・同一話者）

| 手法 | 最良 N | macro-F1 | 二値分離 | CER |
|---|---|---|---|---|
| Encoder 凍結 | 1 | 0.722 | 0.650 | 23.3 |
| LoRA | 0 | 0.725 | 0.658 | 23.8 |
| **Adapter (s=0.4)** | 0 | **0.729** | 0.656 | 23.9 |

**Adapter が最良**。LoRA とほぼ同じ ASR コスト（+0.6 vs +0.5）で macro-F1 が +0.004 上回る。

### 4.2 得られた主要な知見

1. **適応量の制御が有効**（本実験の中心的成果）。補正量に上限 s を課すことで、s≤0.2 では ASR を完全に保ったまま（CER 23.3）タグ性能を +0.007 改善できた。「エンコーダ適応は必ず ASR を犠牲にする」という当初の想定は誤りで、**適応量を制御すれば ASR をほぼ保ったまま性能を上げられる**。

2. **タグ性能と CER のトレードオフが明確**。適応を強めるとタグは s=0.4〜0.6 で頭打ちになる一方、CER は単調に悪化。適応の膝は s=0.4 付近。

3. **過去発話は3手法すべてで有害**。凍結・LoRA・Adapter のいずれでも N=0 が最良で、N を足すほど単調低下する。文脈の与え方が問題なのではなく、**過去発話を足すこと自体が短い相槌の識別を難しくしている**。

4. **継続/完了の二値分離 0.65 は動かない**。文脈量・文脈種別・適応手法・適応強さのどれを変えても 0.63〜0.66 に留まる。これは**モデル側の表現力ではなく、ラベル品質（LLM 付与 F1 0.805）やタスク定義の曖昧さ**が上限を規定している可能性を強く示唆する。

### 4.3 本実験の限界

- 探索したのは Adapter の適応強さ s のみ。ボトルネック幅（32 固定）、挿入箇所（主 FFN 12 箇所固定）、学習率などは未探索であり、さらに良い設定が存在しうる。
- s の選定は N=0 で行い、N を振る際は固定した（過去発話を入れると最適点がずれる可能性は残る）。
- 学習パラメータ数は LoRA 395 K に対し Adapter 497 K（適応部分は 98 K vs 200 K）で厳密には揃っていない。
