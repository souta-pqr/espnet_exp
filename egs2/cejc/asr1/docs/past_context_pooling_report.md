## 1. 何を問いたかったか

中間審査時点のモデルは、過去 N 発話を凍結エンコーダで符号化したあと **max pooling で 1 本のベクトルに潰して**いた。ここには暗黙の仮定がある。

> 過去がどれだけ長くても、区間末の判定に必要な情報は 1 本のベクトルに収まる

この仮定を検証していなかった。そこで「過去を**何本の記憶スロット**にしてヘッドへ渡すか」という一点だけを変える手法群を実装し、比較した。**過去文脈の「量」ではなく「粒度」を問う実験**である。

比較指標を区間末タグの精度だけに絞れるよう、エンコーダ・デコーダ・joint・CTC はすべて凍結した。凍結部は `train()` でも常に eval に固定しているので BatchNorm の統計も動かず、**CER は Stage1 と数値的に同一**になる。実際、後述する 10 手法すべてで CER 23.3 が一致した。

## 2. モデル全体

```
   過去発話の音声（直前 N 発話を連結）        現発話の音声
              │                                  │
     ┌────────▼────────┐                ┌────────▼────────┐      ┌──────────┐
     │ Shared Encoder  │ 凍結❄          │ Shared Encoder  │ 凍結❄ │ Decoder  │ 凍結❄
     └────────┬────────┘                └────────┬────────┘  └──▶└────┬─────┘
              │ p₁ … p_Tp                        │ C₁ … C_T            │
              │ （Tp ≈ 44 @N=1 / 204 @N=5）      │                  テキスト
     ┌────────▼────────┐                         │
     │   過去要約       │ ◀── ここだけを 7 通り    │
     │  tt_past_pool   │      差し替えて比較      │
     └────────┬────────┘                         │
              │ V₁ … V_Np （Np は手法で決まる）    │
     ┌────────▼─────────────────────────────────▼────────┐
     │       Self-Attention（1 層・4 ヘッド）              │ ← 学習
     │       ＋ セグメント埋め込み ＋ 相対位置符号          │
     └──────────────────────┬─────────────────────────────┘
                            │ C′_T ＝ 現発話の最終フレーム位置から読み出し
                      ┌─────▼─────┐
                      │    MLP     │ ← 学習
                      └─────┬─────┘
                   発話区間末タグ（継続 / 完了 / 相槌）
```

学習するのは **self-attention 1 層 ＋ セグメント埋め込み ＋ MLP(256→128→3) ＋ 過去要約モジュール**のみ。損失は 3 クラスの重み付きクロスエントロピー `[1.92, 1.0, 1.63]` だけで、ASR 損失は計算しない。

### 「過去発話」の定義

- 単位は **segments の 1 行 ＝ 1 発話セグメント**。固定長の窓ではない
- `scope=same`（本報告で使用）は**同じ話者チャネル**の直前 N 発話
- 古→新の順に連結。過去発話の開始が「現発話開始 − 30 秒」より前になった時点で打ち切り
- 過去がない発話（会話先頭）は 20 ms の無音。train で約 1.5%

| N | 過去長の中央値 | 平均 | 平均 Tp（フレーム） |
|---|---|---|---|
| 1 | 1.03 秒 | 1.45 秒 | 約 44 |
| 5 | 6.03 秒 | 6.74 秒 | 約 204 |

この実測値が手法比較の設計に直接効く。**N=1 では平均 44 フレームしかない**ので、M=8 スロットは 5.5 倍の圧縮にしかならず、圧縮なしとの差が出にくい。N=5 なら 204 → 8 スロットで 25 倍の圧縮になり、手法の差が現れるはずだった。

## 3. 設計空間 — なぜこの 7 手法なのか

### 3.1 2 つの軸

過去要約は「Tp 本のフレーム列を Np 本のスロット列に変える写像」である。この写像は 2 つの独立な軸で特徴づけられる。**この 2×2 は本研究で整理したものであり、特定のサーベイに由来するものではない**（各軸には個別に先行研究がある）。

**軸 1：出力の本数を何が決めるか**

| | 出力本数 | 背後にある仮定 |
|---|---|---|
| **固定率** | Np = ⌈Tp / c⌉<br>過去が 2 倍になればスロットも 2 倍 | 必要な容量は**過去の長さに比例する** |
| **固定長** | Np = M<br>過去が何秒でも M 本 | 必要な情報量には**上限があり定数で足りる** |

違いが生じる理由は 2 つある。**計算量**の面では、ヘッドの self-attention が (Np+T)² のコストを払うため、固定率は過去が伸びるとコストが二乗で増えるのに対し、固定長なら一定である。もう一つは**仮説そのものが違う**点で、どちらが正しいかは測らないと分からないため両方を実装した。

**軸 2：出力の値が入力の値そのものか**

| | 出力の作り方 | 性質 |
|---|---|---|
| **soft**（混ぜる） | 入力ベクトルの重み付き和・変換。**入力に無かった新しい値**が出る | 全部微分可能で学習しやすい |
| **hard**（選ぶ） | 入力ベクトルの**部分集合**。選ぶだけで値は変えない | 選択が微分不可能なので工夫が要る |

こちらが重要なのは**表現が壊れうるから**である。凍結エンコーダの出力は ASR 用に最適化された表現で、「この時刻は文末表現」といった構造を持っている。soft で異なる時刻の値を平均すると、その構造が混ざって失われる可能性がある。hard なら残したものはそのまま渡る。副次的に、hard は「どのフレームを選んだか」がインデックスで観察できるという利点もある。

### 3.2 軸を掛けた配置

**既存手法は左下の一点に張り付いていた。**

| | soft（混ぜる） | hard（選ぶ） |
|---|---|---|
| **固定率**<br>出力 ∝ 過去長 | `conv` … Np = ⌈Tp/c⌉<br>（`frames` は c=1 の端点） | — |
| **固定長**<br>出力 = M 本 | `query` … Np = M<br>（`attn`・`max` は M=1 の特殊ケース） | `topk` … Np = min(M, Tp) |
| **会話単位**<br>出力 = 有効発話数 × k | `utt` … 発話境界で区切って要約 | |

3 行目は 2×2 の外にある。出力本数を決めるのが比率でも定数でもなく、**内容の構造（発話数）**だからである。上 2 行の区切りは固定率・固定長という音響的に無意味な切り方で、`utt` だけが会話の単位で区切る。

### 3.3 なぜ軸を分ける必要があったか

もし固定長の手法だけを試して失敗した場合、「圧縮が悪い」のか「固定長が悪い」のか区別できない。軸を分けて両方を埋めることで、**結果を原因に帰属させられる**。

実際これが効いた。`frames`（＝圧縮なし・固定率の端点）が床と有意差を示さなかったことから、「圧縮方法の問題ではなく、過去音声にそもそも必要な情報が無い」と結論できた（§7.1）。1 手法だけを試していたら、この切り分けはできていない。

### 3.4 各手法が借りている機構

| 手法 | 借りた機構 | 文献 |
|---|---|---|
| `max` | 時間方向の max pooling。既存ベースライン（中間審査時点の構成） | — |
| `attn` | 学習クエリ 1 本による attention pooling | [8]（r=1 の場合）／`query` の M=1 特殊ケース |
| `frames` | 過去を圧縮せずキャッシュして繋ぐという考え方 | [4] |
| `conv` | compression function としての 1D 畳み込み | [1] |
| `query` | 学習シードによる cross-attention で固定長に落とす（PMA / latent bottleneck） | [2][3] |
| `topk` | compression function の "most-used"（注意質量の大きい状態を残す） | [1]／源流は hard attention [9] |
| `utt` | 発話単位で階層的に符号化する対話モデルの定式化 | [10]／境界推定の一般解として [11] |

## 4. 各手法の仕組みと、なぜ良くなると考えたか

### 4.1 max / attn — 既存手法（Np = 1）

```
p₁ p₂ p₃ … p_Tp
      │
      ▼
 ┌──────────────────────────────┐
 │ max pooling（パラメータなし）  │  または
 │ 学習クエリ 1 本の attention    │
 └──────────────┬───────────────┘
                ▼
               V₁              ← 過去が何秒あっても常に 1 本
```

**内容**: 過去フレーム列を 1 本のベクトルに潰す。`max` は各次元の最大値を取るだけで学習パラメータがない。`attn` は学習可能なクエリ **q** との内積を softmax で重みにして加重平均する（パラメータは 256 個）。

**なぜ良くなると考えたか**: `max` は「過去のどこかに強く反応した特徴」を拾うが、どのフレームを重視するかを学習できない。`attn` なら「区間末の判定に効く過去の部分」に重みを集中させられるので、同じ 1 本でも情報の質が上がるはず、という仮説。

---

### 4.2 frames — 圧縮しない（Np = Tp）

```
p₁ p₂ p₃ … p_Tp   →   そのまま   →   p₁ p₂ p₃ … p_Tp
                                     Np = Tp（N=5 なら約 204）
```

**内容**: pooling を一切せず、過去の全フレームをそのまま self-attention に渡す。self-attention は (Np+T)² のコストを払う。

**なぜ良くなると考えたか**: 圧縮による情報損失がゼロなので、**「自分の過去音声」が持つ情報量の上限**を与える。他手法がこれに届かなければ圧縮のせい、届いてしまえば圧縮は無害、と切り分けられる。比較の基準点として最も重要な条件。

---

### 4.3 conv — 固定率・soft（Compressive Transformer 型）

```
過去フレーム列
 p₁ p₂ p₃ p₄ p₅ p₆ │ p₇ p₈ p₉ p₁₀ p₁₁ p₁₂ │ p₁₃ …
 └──── c フレーム ───┘ └───── c フレーム ─────┘
          │                      │
   ┌──────▼──────────────────────▼──────┐
   │  Conv1d(kernel = stride = c)        │  ← 学習あり（既定）
   │  または mean / max（非学習）         │
   └──────┬──────────────────────┬──────┘
          ▼                      ▼
         V₁                     V₂          出力 = ⌈Tp / c⌉ 本
                                            （過去が長くなればスロットも増える）
```

**内容**: Transformer-XL [4] が過去を「キャッシュしてそのまま繋ぐ」のに対し、Compressive Transformer [1] はその先で古い状態を**固定率で圧縮した記憶スロット**に落とす。圧縮関数は論文の compression function に対応し、`conv`（学習あり・既定）/ `mean` / `max`（非学習）から選べる。パディング位置は 0 にしてから圧縮するので無効フレームは混ざらない。

**なぜ良くなると考えたか**: 過去に必要な容量が**長さに比例する**なら、固定長より固定率のほうが自然である。加えてこの手法は既存 2 点を端点として含む — c=1 なら `frames` と完全一致、c ≥ Tp なら `max` と同じ粒度になる。**c を 1 → 8 → 16 → 32 と上げていけば、どこで精度が落ち始めるかが「区間末の判別に必要な時間解像度」の測定値になる**。既存 2 点の間に連続した曲線を引けるのがこの手法の役割だった。

---

### 4.4 query — 固定長・soft（Set Transformer PMA / Perceiver 型）

```
過去フレーム列（長さ可変）
 p₁ p₂ p₃ … p_Tp
  │  │  │     │
  └──┴──┴─────┴──▶  Key / Value
                        ▲
   学習クエリ（シード）    │  cross-attention（4 ヘッド）
   q₁ q₂ … q_M  ─────────┘
    │  │      │
    ▼  ▼      ▼
   V₁ V₂ …  V_M          出力 = 常に M 本（過去長に依らない）
```

**内容**: Set Transformer の PMA（Pooling by Multihead Attention）[2] と Perceiver の latent bottleneck [3] と同じ機構。入力側の長さが可変でも、**学習可能な「シード」の本数で出力サイズが決まる**ため、長い過去を固定サイズに落とせる。

**なぜ良くなると考えたか**: 既存の `attn` は本手法の **M=1・単一ヘッドの特殊ケース**にあたる。M を増やしても精度が伸びなければ「1 本で足りていた」、伸びるなら「潰しすぎていた」と直接的に言える。「1 本のベクトルでは足りないのか、足りるとして何本必要か」という問いに、他の条件を変えずに答えられる設計。

---

### 4.5 topk — 固定長・hard（most-used）

```
過去フレーム列   p₁  p₂  p₃  p₄  p₅  p₆ …  p_Tp
重要度スコア     s₁  s₂  s₃  s₄  s₅  s₆ …  s_Tp
                          │
                  上位 M 本を選択（残りは捨てる）
                          ▼
選ばれたフレーム       p₂      p₅      p_Tp     ← 値は混ぜずそのまま
                       V₁      V₂       V₃      出力 = min(M, Tp) 本
```

**内容**: Compressive Transformer [1] の compression function の一つ **“most-used”**（注意質量の大きい状態を残し、残りを捨てる）に相当する hard compression。上の 2 手法が元の値を混ぜ合わせるのに対し、こちらは**凍結エンコーダの表現をそのまま残す**点が違う。選択は微分できないため、選ばれたフレームに重要度スコアを掛けて勾配を通す。

**なぜ良くなると考えたか**: soft な混合は、異なる時刻の表現を平均することで**元の表現が持っていた構造を壊す**可能性がある。凍結エンコーダの出力は ASR 用に最適化された表現なので、混ぜずに残したほうが下流のヘッドにとって扱いやすいかもしれない。同じ M で `query` と対比すれば、混合による劣化があるかを切り分けられる。加えて選択インデックスを見れば「モデルが過去のどこを見ているか」も観察できる。

---

### 4.6 utt — 会話単位（発話境界で区切る）

```
past_bounds.scp から発話境界を復元
過去音声（連結）   [── 発話 N-2 ──][── 発話 N-1 ──][── 発話 N ──]
凍結エンコーダ      p₁ … p₈          p₉ … p₁₅        p₁₆ … p₂₀
                       │                 │                │
                    要約(max/mean/attn)  要約             要約     ← k = 1 発話あたりのスロット数
                       ▼                 ▼                ▼
                    V_{N-2}           V_{N-1}            V_N       出力 = 有効発話数 × k
```

**内容**: 中間審査スライドの V_{N−2}, V_{N−1}, V_N と同じ粒度を、**事前計算ではなく学習ループの中で**作る。事前計算版（`past_vec`）との違いは、境界を `past_bounds.scp` から復元するので過去長・発話数が可変でよく、要約関数に `attn`（学習あり）を選べる点。`past_bounds.scp` が無いとエラーで止まる。

**なぜ良くなると考えたか**: 固定率も固定長も、**発話境界を無視した音響的に無意味な切り方**である。会話は発話という単位で構成されているのだから、その単位で区切って要約するほうが自然ではないか。境界情報そのものに価値があるかを測る対照条件。

## 5. 実験条件

7 手法（max / attn / frames / conv / query / topk / utt）を N=1 と N=5 で学習した。**pool 固有のキー以外は全条件で完全に一致**している。

| 項目 | 値 |
|---|---|
| Stage1 | `20260713-pureasr`（Contextual Block Conformer + Transducer） |
| 凍結 | frontend / normalize / encoder / decoder / joint_network / ctc |
| batch_bins / accum_grad | 700000 / 8 |
| max_epoch / patience | 30 / 10 |
| 最適化 | Adam, lr 0.002, warmup 25000 |
| クラス重み | `[1.92, 1.0, 1.63]`（継続 / 完了 / 相槌） |
| チェックポイント | `valid.loss.ave`（全条件で統一） |
| 評価 | eval 23,444 区間（継続 6,255 / 完了 10,906 / 相槌 6,283） |

> **注**: 実験途中で `asr.sh` の過去入力の配線が Stage 10（統計計算）にしかなく **Stage 11（学習）に無かった**ことが判明した。それ以前の実験は `tt_past_pool` を何にしても過去発話が学習ジョブに届いていなかった。修正後に全条件を回し直しており、本報告の数値はすべて修正後のもの。各実行スクリプトは起動時にこの配線を検査し、無ければ学習せず中止する。

## 6. 結果

CER は凍結条件により全手法で 23.3（Stage1 と内訳まで一致）。したがって比較はタグ性能のみ。

| conv c=6 | 0.721 | 0.511 | 0.730 | 0.901 | 23.3 |
| query m8 | 0.702 | **0.538** | 0.684 | 0.914 | 23.3 |
| topk m8 | 0.718 | 0.531 | 0.720 | 0.908 | 23.3 |

| | acc | 継続 F1 | 終了 F1 | 相槌 F1 | CER |
|---|---|---|---|---|---|

| max | 0.716 | **0.553** | 0.698 | **0.920** | 23.3 |

### F1 では手法の優劣が判定できない

上の表を見ると、継続 F1 が高い手法（max 0.553）は終了 F1 が低く（0.698）、終了 F1 が高い手法（attn 0.752）は継続 F1 が低い（0.506）。**同じトレードオフ曲線の上を滑っているだけ**の可能性がある。

実際、**同じモデルでチェックポイントを変えるだけで、継続/終了の二値分離が手法間の差より大きく動いた**（同一モデル内 0.639→0.677 に対し、手法間は 0.634〜0.667）。F1 も accuracy も「ある 1 点での性能」しか測っていないため、閾値の位置が偶然どこに落ちたかを比べていることになる。

そこで閾値に依らない **継続 vs 終了 AUC** を主指標として測り直した。

| 手法 | N | 継続/終了 AUC | 床との差 | 95% CI | 有意 |
|---|---|---|---|---|---|
| attn + LoRA | 5 | 0.720 | +0.0130 | [+0.009, +0.017] | あり |
| max | 5 | 0.717 | +0.0099 | [+0.006, +0.014] | あり |
| attn | 5 | 0.715 | +0.0071 | [+0.002, +0.012] | あり |
| utt k=1 | 5 | 0.714 | +0.006 | — | — |
| conv c=26 | 5 | 0.712 | +0.004 | — | — |
| topk m8 | 1 | 0.711 | +0.003 | — | — |
| topk m8 | 5 | 0.709 | +0.001 | — | — |
| **frames** | 5 | **0.708** | **+0.0005** | **[−0.004, +0.005]** | **なし** |
| **過去なし（床）** | 0 | **0.708** | — | — | — |
| query m8 | 5 | 0.705 | −0.003 | — | — |
| conv c=6 | 1 | 0.705 | −0.003 | — | — |
| query m8 | 1 | 0.698 | −0.0095 | [−0.014, −0.005] | あり（悪化） |

ブートストラップ 1000 回・n=17,161。**床が集団の真ん中にある。** 11 条件のうち 3 条件は床を下回り、上回る条件も +0.013 以内に収まる。

## 7. 考察 — なぜ効かなかったか

### 7.1 圧縮方法の問題ではない

**`frames` が床と有意差を示さなかった**ことが決定的である。`frames` は過去を一切要約せず全フレームを渡す条件で、「自分の過去音声」が持つ情報量の**上限**にあたる。それが床と区別できない以上、**要約方法をどう工夫しても上限がゼロ**である。conv・query・topk・utt の優劣を議論する意味がここで消えた。

### 7.2 容量の問題でもない

学習データすら当てられていない。train accuracy は全条件で 0.70 前後に張り付き、パラメータを 7 倍にしても、過去を無圧縮で渡しても動かなかった。

| 条件 | train acc 最高 | 学習パラメータ |
|---|---|---|
| 過去なし N=0 | 0.701 | 297 K |
| attn N=5 | 0.702 | 297 K |
| frames N=5（過去 204 スロット全部） | 0.704 | 297 K |
| conv c=26 N=5 | 0.703 | **2.00 M** |
| attn + LoRA N=5（エンコーダ適応） | **0.708** | 396 K |

過学習でも最適化の失敗でもなく、**必要な情報がヘッドに届いていない**。唯一わずかに動いたのがエンコーダ適応（LoRA）だった点は、後述の方向と一致する。

### 7.3 ラベルの生成過程に立ち返ると説明がつく

タグ付与は Qwen3-8B が **書き起こし＋前後 10 発話＋話者・発話時間・ポーズ長・重複発話** から行っている。判断基準の 4 つ（独り言／明確な質問／ターンを譲りうる文末形式／話題の大きな切り替わり）はすべて言語・談話レベルであり、**声の高さ・強さはラベル生成過程に入っていない**。

この事実が観測を一通り説明する。

| 観測 | 説明 |
|---|---|
| 相槌の one-vs-rest AUC が 0.990 で飽和 | 相槌は固定リストによる**語彙判定**。ASR エンコーダが最も得意な情報 |
| 韻律特徴が弱い（発話末 0.5 秒でエネルギー傾斜 0.564 / F0 傾斜 0.525 / 末尾 F0 0.511） | **ラベルが韻律に依存していない**ので、韻律から当てられないのは当然 |
| 正解書き起こしの語彙特徴を足しても +0.003 | 凍結エンコーダは表層の語彙・文末表現をすでに取り切っている |
| 過去文脈がどのモダリティでも効かない | 正解書き起こしを使った線形モデルでも、現発話のみ 0.704 → 前 3 発話つき 0.705（+0.001）。LLM の 4 基準のうち 3 つは**現発話だけで決まる** |

**中間審査 7 ページの「音声は韻律・発話速度を持つので発話区間末予測に有効」という主張は、この実験設計では原理的に検証できない。** ラベル自体が音を聞かずに作られている以上、音声モデルは完璧なテキストモデルを超えられない構造になっている。検証するには、音を聞いた上でラベルを付け直す必要がある。

### 7.4 一方で、end-to-end であること自体には価値があった

ラベルが書き起こし由来なら「ASR してからテキスト分類器に通せばよい」という反論が立つ。実際に比較した。

| 構成 | テキスト源 | 継続/終了 AUC |
|---|---|---|
| 理想カスケード | 正解書き起こし（実運用では入手不可） | 0.718 |
| 実カスケード | ASR 認識結果（CER 23.3%） | 0.693 |
| **音声 end-to-end**（attn N=5） | — | **0.715** |

**実カスケードを +0.022 上回り、正解書き起こしを使った理想カスケードにほぼ並ぶ。** 現行モデルは認識誤りに影響されずに書き起こし相当の判別性能を出している。精度の絶対値では床から大きく離れられないが、**この頑健性は中間審査 5 ページの「ASR とマルチタスクで」という設計の、初めての定量的な裏づけ**になる。

## 8. 結論と今後

### 結論

1. **過去発話の要約手法は、区間末予測を改善しない。** 固定率・固定長・hard・会話単位の 4 軸で設計空間を張ったが、圧縮なしの `frames` でさえ床と有意差がない。これは手法の失敗ではなく、**「自分の過去音声」に必要な情報が入っていない**ことの証明である
2. **F1 だけの比較は手法の優劣を判定できない。** 閾値に依らない AUC を併用しないと、動作点の偶然を比べることになる
3. **end-to-end 構成には測定可能な優位がある。** 実カスケード比 +0.022

### 今後

**(a) デコーダ状態をタグヘッドへ接続する**（実装済み・未学習）

現行のヘッドが見ているのはエンコーダ出力 C′_T だけで、モデル内で唯一言語を担う Transducer デコーダの状態はテキスト出力に使われるのみでタグ側に届いていない。タグは「伝えたいことを言い終えたか」という意味・語用の判断なのだから、**判断に必要な情報を持つ唯一のモジュールを判断に使っていなかった**ことになる。

デコーダは凍結したまま状態列を線形射影し、`[過去 ; デコーダ状態 ; 現発話フレーム]` として self-attention に入れる。ASR で既に計算済みなので追加コストはほぼゼロ。全体図に **Decoder → Self-Attention の線を 1 本足す**変更にあたる。

```
pureasr_tag=20260713-pureasr N=5 ./run_pool_dec.sh
```

**(b) 精度ではなく「早さ」を主軸にする**

精度の天井は 0.72 前後にあり、動かすのが難しいことが今回の測定でわかった（正解書き起こしを使った理想カスケードでも 0.718）。一方、中間審査 19〜21 ページの早期確定は**まだ測っていない開いた軸**であり、背景に挙げた「応答遅延」に直結する。同じ精度をどれだけ早く出せるかのトレードオフ曲線を引くほうが、貢献として明確になる。

**やらないと決めたこと**

- 過去発話の要約手法をさらに増やす（`frames` が上限ゼロを示している）
- 過去テキスト版の再実行（文脈自体がほぼ効かない）
- 韻律特徴の明示的な追加（ラベルが韻律に依存していない）
