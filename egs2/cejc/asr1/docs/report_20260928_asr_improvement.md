# 音声認識の精度を上げると，発話区間末検出も良くなるか

作成日: 2026-09-28（2026-10-02 更新：音声経路の結果を追記／2026-10-05 更新：N-best の取り直し，block_size 60 の途中経過を追記）

音声モデル（Stage2）側の改良は別資料 `docs/report_20261005_audio_model_improvement.md` にまとめた．

## 行ったこと

- レイテンシを変えずに，音声認識（Stage1）の CER を 23.3% から **20.7%** に下げた．
- 新しい音声認識を使うと，発話区間末検出がどれだけ良くなるかを確かめた．
    - テキスト経路：誤割り込みはほぼそのままで，**応答ミスが 0.01 前後減った**．
    - 音声経路：応答ミスがさらに 0.01 前後減った．誤割り込みの増加は 0.004 以内．
    - 両方を合わせると，macro-F1 は **0.7429 → 0.7537** になった．

---

## 1. 音声認識を改善した理由

- これまでの融合（音声モデル ＋ 認識結果を BERT で読んだ判定）の結果は次のとおり．
    - 実際の認識結果を使った場合：macro-F1 0.7461
    - 正解の書き起こしを使った場合（理想）：macro-F1 0.7829
- この差は**認識誤り**によるもので，融合の方法をいくら工夫しても縮まらなかった．
- → 発話区間末検出を良くするには，**音声認識そのものを良くする**のが近道だと考えた．
- ただし，**レイテンシ（応答の遅れ）は増やさない**．早さを犠牲にしては意味がないためである．

---

## 2. 音声認識の改善

### 変更点

| 変更 | 内容 |
| --- | --- |
| 学習の延長 | 元の学習は上限の 50 エポックで止まっており，まだ改善が続いていたため延長した |
| 学習率 | 学習済みのモデルから続けて学習するため，学習率を下げた |
| **block_size** | エンコーダが一度に見る範囲を広げた（次節で説明） |
| 速度摂動 | 音声を 0.9 倍速・1.1 倍速にした複製を加え，学習データを 3 倍にした |
| CTC 補助損失 | 補助の損失を追加した |

- 学習率と block_size は最初の実験で同時に変えてしまった．そこで学習率だけを変える対照実験を追加し，それぞれの効果を切り分けた．

### block_size を広げてもレイテンシが増えない理由

- ストリーミング用のエンコーダ（Contextual Block Conformer）は，音声を小さなブロックに区切って処理する．
- 各ブロックは「過去」「現在」「未来（先読み）」の 3 つの部分からなる．

```
過去の長さ = block_size − hop_size − look_ahead
```

- **レイテンシを決めるのは未来（look_ahead）の長さだけ**である．過去をいくら長く見ても，応答は遅れない．
- そこで look_ahead はそのままにして，block_size だけを 18 から 42 に増やした．

| | block_size | 見える過去 | レイテンシ |
| --- | --- | --- | --- |
| 変更前 | 18 | 約 0.40 秒 | 約 100 ms |
| 変更後 | 42 | 約 1.19 秒 | **約 100 ms（変化なし）** |

### 結果

上から順に変更を積み重ねたときの値．

| 実験 | CER (%) | WER (%) |
| --- | --- | --- |
| 元のモデル | 23.3 | — |
| ＋ 学習の延長 | 22.5 | 30.0 |
| ＋ 学習率を下げる | 22.1 | 29.4 |
| ＋ block_size 42 | 21.2 | 28.2 |
| ＋ 速度摂動 | **20.7** | **27.4** |
| （＋ CTC 補助損失） | 効果なし | — |

- 各変更の寄与（CER）
    - 学習の延長：−0.8
    - 学習率：−0.4
    - **block_size：−0.9**（最大）
    - 速度摂動：−0.5
- **合計 −2.6 ポイント．レイテンシは変わっていない．**

### 分かったこと

- 最も効いたのは block_size だった．過去を長く見るだけで，遅れを増やさずに精度が上がる．
- 速度摂動は効果が出るまでに時間がかかった（それまでの最良を超えるのに 7 エポック）．途中で頭打ちと判断して止めていたら，効果を見逃していた．
- 学習中の指標（valid loss）では学習率の変更が最も効いたように見えたが，CER では block_size の方が効いていた．**どの変更が効いたかは，必ず CER で判断する**必要がある．

## 3. 音声認識の改善は，発話区間末検出に効くか

効き方には 2 つの経路がある．

| 経路 | 仕組み |
| --- | --- |
| テキスト経路 | 認識結果がきれいになる → BERT の判定が良くなる → 融合が良くなる |
| 音声経路 | エンコーダの表現が良くなる → 音声モデルの判定が良くなる |

まずテキスト経路だけを変え，次に音声経路も変えることで，2 つの寄与を分けて測った．
判定はどれも区間検出（発話末の 0.25 秒後）まで待ってから行い，音声とテキストを混ぜる重みごとに比べた．

### テキスト経路

- 音声モデルは**古いまま固定**し，**認識結果だけ**を新しいものに差し替えた．
    - → 差は純粋に「認識精度が上がった分」だけになる．

| 音声の重み | 応答ミス（旧 → 新） | 誤割り込み（旧 → 新） |
| --- | --- | --- |
| 0.3 | 0.314 → **0.300** | 0.184 → 0.184 |
| 0.4 | 0.303 → **0.290** | 0.188 → 0.187 |
| 0.5 | 0.293 → **0.280** | 0.195 → 0.194 |
| 0.6 | 0.278 → **0.270** | 0.204 → 0.203 |

- **どの重みでも，誤割り込みはほぼ変わらず（差 0.001 以内），応答ミスだけが 0.008〜0.014 下がった．**
    - 誤割り込みがそろった状態での比較なので，片方を下げてもう片方が上がったのではなく，純粋な改善といえる．
- つまり認識精度の改善は，主に「言い終えた」の見逃し（応答ミス）を減らしている．

テキストだけで判定したときのクラス別 F1 も，これと合っている．

| | 継続 F1 | 完了 F1 | 相槌 F1 |
| --- | --- | --- | --- |
| 旧（CER 23.3） | 0.564 | 0.704 | 0.930 |
| 新（CER 20.7） | 0.571 | **0.718** | 0.939 |

- **最も伸びたのは完了 F1** だった．
    - 以前は「テキストは継続の判定には効くが，完了の判定には効かない」と考えていた．
    - 実際には，認識誤りで文末が崩れていたことが原因だった可能性がある．
- 参考：macro-F1 は 0.7429 → **0.7500**．これまでの最良（N-best 融合の 0.7461）を，1-best のまま上回った．

### 音声経路

- 新しい音声認識のエンコーダの上で，音声モデルを学習し直した．
    - block_size が変わったため，以前の音声モデルはそのままでは使えない．
- テキスト側は新しい認識結果に固定し，音声モデルだけを新旧で比べた．

| 音声の重み | 応答ミス（旧 → 新） | 誤割り込み（旧 → 新） |
| --- | --- | --- |
| 0.3 | 0.300 → **0.290** | 0.184 → 0.187 |
| 0.4 | 0.290 → **0.281** | 0.187 → 0.191 |
| 0.5 | 0.280 → **0.270** | 0.194 → 0.198 |
| 0.6 | 0.270 → **0.257** | 0.203 → 0.206 |
| 1.0（音声のみ） | 0.248 → **0.231** | 0.244 → 0.247 |

- **応答ミスがさらに 0.009〜0.017 下がった．** 誤割り込みは 0.003〜0.004 上がったが，応答ミスの減少の方がずっと大きい．
- 音声だけで判定したときの macro-F1 は 0.7306 → **0.7354**．

### 両方の経路を合わせた結果

| 条件 | macro-F1 |
| --- | --- |
| 出発点（音声・テキストとも旧） | 0.7429 |
| テキスト経路だけ新しく | 0.7500（+0.0071） |
| **音声経路も新しく** | **0.7537**（さらに +0.0037） |
| 理想（正解の書き起こし） | 0.7839 |

- 理想との差は 0.0410 から **0.0302** になり，約 4 分の 1 縮まった．
- 寄与の大きさはテキスト経路が約 2 倍．
- 学習中の検証損失では，新しい音声モデルは旧モデルが 39 エポックかけた値に 17 エポックで並んでいた．しかし macro-F1 の差は +0.0037 にとどまった．ここでも**学習中の指標だけで判断してはいけない**ことが確かめられた．

### N-best 融合は効かなくなった（2026-09-30）

- 旧い音声認識では，認識候補を 5 つ出して BERT の判定を ASR スコアで重み付け平均する「N-best 融合」が，融合側の工夫で唯一効いていた（+0.0032）．
- 新しい音声認識で取り直した．重みと温度は開発データで選んだ．

| 条件 | 旧い音声認識 | 新しい音声認識 |
| --- | --- | --- |
| 1-best 融合 | 0.7429 | **0.7537** |
| N-best 融合（開発データで選択） | 0.7461（+0.0032） | 0.7532（**−0.0005**） |
| オラクル N-best（正解に最も近い候補を選ぶ・到達不能） | 0.7498（+0.0069） | 0.7587（+0.0050） |
| 1 位候補の CER 平均 | 0.351 | 0.307 |

- **新しい音声認識では N-best は効かない．** 開発データでは +0.0039 だったが，評価データでは逆に下がった．
- 1 位の認識結果が良くなった分，2 位以下の候補から得られる上積み（オラクルの上限）も縮んだ．
- → **音声認識を良くすると，認識結果を後から工夫して使う余地は減る．** 融合のテキスト側はここで打ち止めとした．

---

## 4. 注意点

- 以前の別のモデル（CER 19.6%）の方が良く見えるが，**比較はできない**．
    - そのモデルはカタカナ（発音）で出力・採点していた．今のモデルは漢字かな交じりで採点している．
    - 発音で採点すると漢字の読み違いが誤りにならないため，CER は低く出る．
    - 評価データも入れ替わっており，共通する区間は 4 割程度しかない．
- 音声認識を新しくすると，**これまでの音声モデルの実験はすべてやり直し**になる（block_size が変わるため）．
