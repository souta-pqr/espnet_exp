# 発話区間末検出：各手法の詳細解説（図つき）

作成日: 2026-07-08
結果一覧は [turntaking_methods_summary.md](turntaking_methods_summary.md)。本書は「**どういう仕組みか**」を図と具体例で解説する。

## タスクと共通の土台
発話を最後まで聞いて、その区間の発話区間末タグを1つ予測する（早期確定なし・未来音声なし）。
- `<継続>`=発話区間末でない / `<完了>`=発話区間末 / `<相槌>`=相槌
- 共通土台：Contextual Block Conformer エンコーダ ＋ Transducer(ASR) のマルチタスク。
- **どの手法でも ASR（音声→テキスト）は現発話のみで不変**。区間末ヘッドだけが手法ごとに変わる。

---

# 手法0：文脈なし（ベースライン）
現発話だけを使う。過去情報なし。

```
  現発話音声 [start, end]（未来なし）
        │
   共有エンコーダ ── encoder出力 ──► Transducer デコーダ → テキスト（ASR・不変）
        │
        └─ 発話全体で平均（現発話の要約 256次元）
                  │
                  ▼
                MLP → 発話区間末タグ（継続/完了/相槌 を1つ）
```

---

# 手法1：過去文脈を「特徴ベクトル」で注入（ctx方式・encoder出力）

## 文脈ベクトルの作り方
1. **1発話を「ベクトル1本」に要約する（uvec）**
   - 学習済み encoder で各発話を特徴ベクトルに変換し、有効フレームを平均プール（時間方向）→ **uvec（256次元）**。
2. **現発話の文脈ベクトルを作成（ctx_vec）**
   - 直前N発話（同じ話者）の uvec を平均 → **ctx_vec（256次元）**。直前の発話がないならゼロベクトル。

   ```
   直前発話 -> encoder -> (T×256) -> 時間平均 -> uvec -> 平均 -> ctx_vec
   ```

- **具体例（N=1）**
   ```
   同じ話者の連続発話:
     - 直前 :「はいだいじょうぶですよ」
     - 現発話:「すみません」 ← これを 継続/完了/相槌 判定

   uvec(直前)     = encoder(「はいだいじょうぶですよ」の音声) を全フレーム平均 → 256次元
   ctx_vec(現発話) = uvec(直前)
   ```

## モデルへの渡し方（ASRには影響ない）
```
  現発話音声 [start, end]（未来なし）
        │
   共有エンコーダ ── encoder出力 ──► Transducer デコーダ → テキスト（ASR・不変）
        │
        └─ 発話全体で平均（現発話の要約 256次元）
                  │  ⊕ ctx_vec(256)   ← 過去N発話の要約
                  ▼
                MLP → 発話区間末タグ（継続/完了/相槌 を1つ）
```

## 過去発話の「集め方」3通り（ctx_vec の作り方だけ差し替え・モデルは不変）
### 1-A. same：同一話者の直前N発話（自分の履歴）
```
（同一話者 IC01 の時系列）… 発話i-2  発話i-1 │ 発話i(現)   ← i-1,i-2 の uvec 平均
```
「自分が直前に何を話していたか」を渡す。相手の発話は入らない。

### 1-B. session：両話者の直前N発話（相手も含む会話履歴）
```
（セッション・両話者を時刻順）
 … IC02「うんうん」 IC01「〜あって」 │ IC01「そうそう」(現)   ← 直前N（相手の発話も含む）
```
同じセッションを時刻ソートで統合し、話者問わず直前N発話の uvec を平均。

### 1-C. cluster：過去の類似発話 top_k を集めて平均（類似検索）
```
（セッションの過去発話のうち、現発話に似たものを top_k 件）
 過去発話群 ──cos類似で上位k件を選抜──► 平均 → ctx_vec
```
recency（直前）でなく **uvec のコサイン類似**で過去から集める。現発話より後は使わない。

# 手法2：過去文脈を「生特徴量(log-mel fbank)」で注入（ctx方式・encoder非経由）

手法1と**過去要約の作り方だけ**が違う。encoder を通さず、**生の音響特徴量**で要約する。

## 文脈ベクトルの作り方（生特徴量）
1. **1発話を「ベクトル1本」に要約する（uvec_raw）**
   - 音声 → フロントエンド（log-mel fbank）→ フレームごと80次元の列（T×80）。
   - **encoder には通さず**、この生 fbank を時間平均 → **uvec_raw（80次元）**。
   - ＝「その発話の平均スペクトル（声の高さ・音量・音色）」を80個の数字で要約。内容の抽象化はしない。
2. **ctx_vec 作成**：直前N発話（同話者）の uvec_raw を平均 → ctx_vec（80次元）。

   ```
   直前発話 -> log-mel fbank (T×80) -> 時間平均 -> uvec_raw(80) -> 平均 -> ctx_vec
             （↑ encoder は通さない）
   ```

- **具体例（N=1）**
   ```
   直前 :「はいだいじょうぶですよ」  現発話:「すみません」
   uvec_raw(直前)  = log-mel fbank(「はい〜」の音声) を全フレーム平均 → 80次元（encoder非経由）
   ctx_vec(現発話) = uvec_raw(直前)
   ```

## モデルへの渡し方（手法1と同じ・concat次元だけ80）
```
  現発話音声 → 共有エンコーダ ─► Transducer → テキスト（ASR・不変）
                    │
                    └─ 発話全体で平均（現発話の要約 256次元）
                              │  ⊕ ctx_vec(80)   ← 過去N発話の「生fbank平均」
                              ▼
                            MLP → 発話区間末タグ
```
狙い：過去の「内容(encoder表現)」が効くのか「音響の色(生特徴)」でも効くのかを切り分ける。

# 手法3：過去音声を連結してエンコーダに通す（seqcat方式）

過去を別ベクトルにせず、**[過去N発話 + 現発話] の音声を時間連結**して共有エンコーダに1回通す。
過去はエンコーダの self-attention で現発話フレームに文脈として畳み込まれる。**ASR は現発話のみ不変**。

## 仕組み
1. 直前N発話（同話者・現発話より前）の音声を、現発話の**前に時間連結**（現発話が必ず最後）。
2. 連結系列を共有エンコーダに1回通す → フレーム列 [過去|現発話]。
3. フレームを **max pooling**（average は使わない＝transformer出力の平均は勾配が均一化して不利）→ 1ベクトル。
4. MLP → タグ。

- **具体例（N=2）**
   ```
   [発話i-2 の音声][発話i-1 の音声][現発話 の音声]  ← 時間連結（現発話が最後）
        └────────── 共有エンコーダ(1回) ──────────┘
                          │
              出力: [==過去 i-2,i-1==][==現発話==]
                          │
                     max pooling → 1ベクトル(256) → MLP → タグ
   ```

## モデル図
```
   [N-2][N-1][現発話]音声を時間連結           （※ASRは別forward）
        │                                     現発話音声
   共有エンコーダ(1回)                             │
        │                                    共有エンコーダ
   フレーム列 [過去|現発話]                          │
        │                                    Transducer → テキスト（不変）
   ★max pooling★（average不使用）
        │
   1ベクトル(256) → MLP → 発話区間末タグ
```

## pooling 範囲の2通り
- **3-A. whole**：連結全体（過去+現発話）を pool。過去も直接ベクトルに寄与。
  ```
  出力 [ p1' p2' | c1' c2' c3' ]  ← 全部を max pool
  ```
  → 長く完結した過去が max を支配し、短い現発話（特に相槌）が飲み込まれて不利（実測で悪化）。

- **3-B. current**：**現発話フレームのみ** pool。過去はエンコーダの前置き文脈としてのみ効く。
  ```
  出力 [ p1' p2' | c1' c2' c3' ]  ← ★c1'..c3'（現発話）だけ★ max pool
                                     （c' は self-attention で過去 p を参照済み）
  ```
  → 「過去の文脈を織り込んだ**現発話**のベクトル」。判定対象＝現発話に一致。

## 手法1（ctx方式）との違い
| | 手法1 ctx方式 | 手法3 seqcat方式 |
|---|---|---|
| 過去の使い方 | 別に要約(uvec平均)して**concat** | 音声を**連結してエンコーダに通す**（文脈として畳み込み） |
| pooling | 現発話・過去とも average | 現発話(or全体)を **max**（average不使用） |
| エンコーダ回数 | 現発話1回 | 現発話1回 ＋ 連結系列1回（重い） |
| ctx次元 | 256/80 | 0（連結で表現） |
