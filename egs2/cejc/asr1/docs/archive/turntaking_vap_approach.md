# 手法転換：CIF-TEASER → VAP-lite フレームレベル turn-taking（設計資料）

作成日: 2026-06-13
対象: `egs2/cejc/asr1` / turn-taking（発話区間末の早期確定）
関連: [methodA_teaser_why_failed.md](methodA_teaser_why_failed.md)（なぜ CIF-TEASER が頭打ちか・診断）/ [cif/method_A_TEASER.md](cif/method_A_TEASER.md)（TEASER 設計）
コード: `local/turntaking/`（model / extract_features / train / evaluate）, `run_turntaking.sh`

> 解きたい問題は変わらない：**ユーザの発話中に「システムがターンを取るべきか」をできるだけ早期に、
> しかし誤判定しない範囲で確定する**。ラベルは区間単位で `<no>`=区間末でない / `<yes>`=区間末 /
> `<other>`=相槌。易しい発話は早く決め、難しい発話はしっかり待つ。
> 本資料は「なぜ CIF-TEASER をやめ、何に変えるのか」を、ダメだった理由から順に説明する。

---

## 1. なぜ手法を変えるのか（CIF-TEASER のどこがダメか）

CIF-TEASER は「CIF が音響をトークン単位の発火(fire)に積算し、各 fire で slave=tag_classifier が
クラス確率を出し、master=stop_head がいつ止めるか判定する」構造だった（[cif/method_A_TEASER.md](cif/method_A_TEASER.md)）。
ここには **3 つの構造的な問題**があり、no/yes の分離が ~0.62 で頭打ちになった。

### 1-1. CIF は沈黙で発火しない（決定打を観測できない）

```
発話：  …行けないです [区間末] ――― 無音 ――― 次話者ターン
CIF発火： ● ● ● ● ● ●  ●        （ここで止まる）
                       ↑最終語で発火が尽きる。以降フレームがあっても fire が出ない
```

> 区間末判定の**決定打は「発話直後の無音／次話者がターンを取るか」**にある（診断 §9）。
> ところが CIF は最終語で発火が止まるので、**まさにその区間末以降を観測する手段がない**。
> 「いつ止めるか」を判定したいのに、止めるべき瞬間の手がかりが入力に入ってこない。

### 1-2. セグメント化で trailing 無音が捨てられている（情報不足）

学習・評価は秒単位 `segments` で**語末ぴったりに切られた**区間を encoder に通していた。
末尾無音の実測は**中央値 0ms**＝区間末以降の無音が物理的に存在しない。

> 根本原因は表現力不足ではなく **情報不足**。slave/master をいくら作り込んでも、
> 入力に no/yes の手がかりが無いので 0.62 を超えない（GRU 再表現・encoder プローブ・過去文脈、
> いずれも 0.60–0.62 で棄却。診断 §4–§5）。

### 1-3. master の教師信号が矛盾する

stop_head の教師 `stop_target` は「その fire で分類が正解か（=隠れ正解 y 依存）」で作るが、
入力 φ（sort 済み確率・margin・entropy 等）は**クラス非依存**で y を判定する材料が無い。
自信満々で外す `<no>` と自信満々で当てる `<yes>` が φ 上ほぼ同一なのに target は 0/1 と食い違い、
stop_head は周辺分布しか学べず stop_acc 0.76 で飽和した（診断 §5.2）。

### 1-4. 診断 §9 が示した活路

各区間を `[start, end+Δ]` で**録音から読み直し**、区間末以降まで観測すると、no/yes 分離は

| Δ（区間末からの追加観測） | 0ms | 300ms | 800ms | 1200ms |
|---:|---:|---:|---:|---:|
| 線形プローブ精度 | 0.62 | 0.63 | 0.68 | **0.70** |

と**単調に改善**した。これは未来の先読み(acausal)ではなく「**待つ**」こと＝標準的な
エンドポイント遅延。情報は録音のセグメント間ギャップに残っており復元できる。

> **結論**：0.62 は streaming の限界ではなく「セグメント化＋遅延0で即決」のアーティファクト。
> ならば設計を **(a) 区間末以降まで連続観測でき、(b) いつ止めるかを適応的に決められる**
> 形に変えればよい。それが本手法。

---

## 2. 何に変えるか（VAP-lite フレームレベル turn-taking）

> 「CIF 発火ごと」ではなく「**音声フレームごと**」に毎時刻 turn-end 確率を出す。
> ASR は凍結したまま並走させ、その encoder 出力に小さな turn-taking ヘッドを載せる。

### アーキテクチャ

```
            （変更しない・凍結）
音声 ─► streaming ASR encoder (contextual_block_conformer) ─► encoder_out (T,256)
            │  ※ASR本来のデコードはそのまま動く（並走）
            ▼
      turn-taking head（学習対象・因果 dilated conv 3層）
            ├─► cls_logits (T,3)   : 各フレームで <no>/<yes>/<other>
            └─► va_logits  (T,B)   : 各フレームで「今後 h 秒以内に対象話者が発話するか」
            │
            ▼  毎フレームの事後確率ストリーム p_t
      停止規則（TEASER 連続 / SPRT 累積）→ 早期確定
```

- **frame = 33ms**（frontend hop 132/16k=8.25ms × conv2d subsample ×4）。look_ahead=3≈100ms。
- head は **因果**（左パディング conv のみ＝未来を見ない）。受容野は dilation 1/2/4・kernel5 で約 28 frame ≈ 0.9s 過去。
- 0.28M params と軽量。ASR の計算遅延は実質増えない。

---

## 3. なぜフレームレベルか（CIF をやめる理由）

> CIF は「トークンを何個出すか」に最適化された発火器で、**沈黙では発火しない**（1-1）。
> turn-taking が本当に見たいのは語そのものではなく「語が途切れたあとの間（ま）」。
> だから発火に同期せず、**無音区間も含めて毎フレーム連続に**判定する frame-level に切り替える。
> これで診断 §9 の「区間末以降を観測する」を、推論時にそのまま実現できる。

---

## 4. なぜ ASR を凍結して「並走」させるのか

制約は「**現在のストリーミング音声認識を変えない**」こと。

> turn-taking ヘッドは encoder_out を読むだけの**横付け**で、ASR の重み・デコード・遅延に触れない。
> ASR は今まで通り認識を続け、その副産物（encoder 出力）を turn-taking が借りる。
> 計算遅延の増加はヘッドの微小コストのみ。**確定の遅延**は固定ではなく、停止規則が
> 発話ごとに「自信があれば即・曖昧なら待つ」と適応的に決める（§7）。

凍結の代償：精度天井は encoder が持つ情報量で決まる（診断では transformer 版で no/yes ~0.70）。
**本手法の利得は精度天井の引き上げではなく、早期性・適応性・自己教師信号**である。

---

## 5. なぜ「未来 VA 予測」を補助タスクに足すのか（VAP の発想）

VAP（Voice Activity Projection）= 「**この先 h 秒で誰が話しているか**」を予測させると、
ターン交替の構造（間の取り方・話者の引き継ぎ）を表現が学ぶ、という考え方。

```
各フレーム t で、対象話者 chが (t, t+h] に発話しているか？を h=0.2/0.4/0.6/1.0s で予測
 → 正解ラベルは segments から自動生成（無料の自己教師。人手アノテ不要）
```

> turn-end の教師は区間単位で 1 個しかないが、VA 予測は**全フレームに密に信号**が付く。
> 「もうすぐ自分は黙る／相手が来る」を予測する力は turn-end 判定と地続きなので、
> 主タスク（cls）の表現を下支えする。ラベルは segments の時間情報だけから作れる（コスト0）。

## 6. 学習方法（段階）

### Stage 0：土台 ASR を学習して固定（freeze）

```
音声 → contextual_block_conformer (transducer) を現データで学習（run_streaming.sh）
→ valid.cer_transducer.best.pth を以降 freeze
```

> 既存モデルは別データ由来の疑いがあるため、**同じ data/ で学習し直す**のが安全。
> turn-taking はこの凍結 ASR の encoder_out を使う。

### Stage 1：特徴抽出（凍結 encoder を1回通してキャッシュ）

各区間を録音から `[start, end+cap]`（cap=1.0〜1.2s）で読み、

- `encoder_out (T,256)` … 区間末以降の trailing 無音まで含む（§1-4 の鍵）
- `va (T,B)` … 未来VA自己教師ラベル（segments から自動生成）
- `label` … 区間単位の tag（0/1/2）

を npz シャードに保存。encoder は凍結なので**1回だけ**通せばよい（`extract_features.py`）。

### Stage 2：turn-taking ヘッドを学習（ヘッドのみ）

```python
入力 : encoder_out (B,T,256)
出力 : cls_logits (B,T,3),  va_logits (B,T,B)
損失 : L = L_cls + λ · L_va           # λ=1.0
  L_cls = Σ_t w(t) · クラス重み付きCE( cls_t , 区間ラベル )   # ラベルは全フレームに broadcast
  L_va  = Σ_t BCE( va_t , 未来VAラベル_t )                     # 自己教師
```

**時間重み w(t)** が要（早すぎ誤判定の抑制と遅延罰の近似）：

```
w(t) = floor + (1-floor) · (t / T) ,  floor=0.1     （t=区間内の位置, T=区間長）
```

> 序盤フレームの誤りは軽く、終盤に近づくほど重く罰する。
> 「序盤は無理に当てなくてよい・終盤は外すな」を損失で表現し、
> **早く決めること（遅延小）と外さないこと（誤判定小）のトレードオフ**を学習に織り込む。
> CIF-TEASER の位置重み（§9 横断注意）と同じ意図を frame 上で実装したもの。

---

## 7. 推論：停止規則による適応的な早期確定

毎フレームの事後確率ストリーム `p_t` に停止規則をかける。発火するまで待ち、発火した時点の
クラスで確定（無発火なら最終フレーム＝最遅）。`evaluate.py` に2方式：

### 7-1. TEASER（確信度ベース）
```
p_max,t > θ  が  同一クラスで v フレーム連続  → 確定
```
4-1 の TEASER と同じ思想を frame 上に移したもの（CIF fire → frame）。

### 7-2. SPRT（証拠累積ベース）
```
累積対数確率 acc += log p_t ;  (top − 2nd) > bound  → 確定
```
> 自信のある発話は数フレームで境界を超えて**即確定**、曖昧な発話は無音/次ターンの証拠が
> たまるまで**自然に待つ**。これが「易しいものは早く・難しいものは待つ」の実体。
> θ や bound を上げるほど精度↑・確定位置（遅延）↑という動作曲線が得られる。

---

## 8. ハイパーパラメータと評価方法

- 学習：λ_va=1.0, floor=0.1, VA horizons=[0.2,0.4,0.6,1.0]s, クラス重み=train 分布から自動。
- 停止規則：θ（TEASER）や bound（SPRT）は**学習せず dev で sweep**し、本番は eval で1回評価。
- 指標：accuracy・クラス別 recall に加え「**確定位置%**（発話のどこで止めたか）」＝早期性。

> **dev とは**：学習・テストと別のチューニング専用データ（ここでは train_dev）。
> テストで閾値を選ぶと過剰適合するので、dev で選んだ設定を eval で 1 回だけ測る（TEASER と同じ作法）。

## 9. CIF-TEASER との対応（何が変わったか）

| 観点 | CIF-TEASER（旧） | VAP-lite（新） |
|---|---|---|
| 判定の単位 | CIF 発火ごと | **音声フレームごと**（沈黙でも出る） |
| 区間末以降の観測 | 不可（発火が尽きる/語末切り）| **可**（cap で trailing を読む） |
| 主タスク | slave 分類 + master 停止の2段 | frame 分類（cls）1本＋時間重み |
| 補助タスク | なし | **未来VA予測（自己教師）** |
| 早期確定 | stop_head（教師が矛盾し飽和）| 停止規則（TEASER/SPRT）を事後適用 |
| ASR | 同上（CIF 付き transformer）| **運用 streaming conformer を凍結・並走** |
| no/yes 上限 | ~0.62（情報不足）| ~0.70（trailing 観測で底上げ）|

---

## 10. 利点・欠点（正直な整理）

**利点**
- 区間末以降の無音/次ターンを推論時に観測でき、no/yes 分離が底上げ（0.62→~0.70）。
- 停止規則で発話ごとの適応遅延：易しい発話は早期確定、曖昧な発話のみ待つ。
- ASR を一切変えない（並走）。未来VAは無料の自己教師で表現を下支え。

**欠点・限界**
- **精度天井は凍結 encoder の情報量で決まる**（~0.70）。これ以上は頭打ち。
- 0.70 で不足なら次のレバーは「生音声を入力に取る並列学習ブランチ」（それでも ASR は触らない）。
- 診断 §9 の数値は transformer 版での実測。**conformer で再抽出すると数値は変わり得る**ので、
  土台 ASR を差し替えたら本手法で再計測して本資料に追記する。
