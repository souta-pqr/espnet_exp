## 0. 目的・問題設定（まずここを合わせる）

ある話者が発話している最中に、「**ここで意味的に一つの発話区間として区切れる（ラベルを置ける）か**」を
判定する。出力は区間単位の 3 クラス：

- `<yes>` … **意味的な発話区間末**。ここで一つの発話単位として完結・区切れる。
- `<no>`  … まだ区間末ではない。意味的に**継続中**（接続・中止形「〜て/〜で/〜けど/〜から/〜し」、
  フィラー(F)、言い直し(D)で作りかけ 等）。
- `<other>` … 相槌。

要件は **精度を落とさずできるだけ早期に**確定すること。易しい発話は早く、曖昧な発話は必要なだけ待つ。

### 本タスクの位置づけ（VAP との違い・重要）

> これは **VAP（Voice Activity Projection／shift・hold ＝ 次に誰がターンを取るかの予測）ではない**。
> 次話者がターンを取るか・無音が来るかを当てるのではなく、**話者自身の発話が意味的に完結したか**を判定する。
> 手がかりの主役は **文末の言語形式（意味・統語）**：独り言／明確な問いかけ／「〜よね・〜でしょ・〜かな」等の
> 譲り表現は `<yes>` 寄り、接続・中止形やフィラー・言いかけは `<no>`。ポーズ・韻律は**補助**にすぎない。
> （テキストのみの LLM で約 8 割当たる事実が、「言語形式が主役」を裏づける。）

> **なぜ「早期」が成立するか**：意味的完結は**発話中の言語形式に現れる**ため、無音や次話者ターンを待たずに
> 判定できる。もし判定が無音・次話者依存なら、間が空くまで待つ必要があり早期決定は原理的に不可能。
> つまり「早く決めたい」という要件自体が、本タスクが**意味的（言語的）**であることを示している。

## 1. なぜ手法を変えたか

先行手法 CIF-TEASER は no/yes 分離が **0.62 で頭打ち**になった。診断（methodA）の結論は
**「表現力不足ではなく情報不足」**。CIF-TEASER でも encoder は ASR と一緒に学習されていた（tag 損失も
encoder に逆伝播済み）ので、**encoder が弱いのが原因ではない**。問題は判定の仕組みが情報を取りこぼすこと：

- **CIF は単語（トークン）が出るたびにしか判定できない**。判定のタイミングが単語の区切りに縛られ、
  好きな瞬間に「いま区切れるか」を出せない（毎フレーム連続には判定できない）。
- しかも**沈黙では発火が止まる**ので、紛らわしい発話で**直後の少しの間（trailing）を見て確かめる**ことができない。
  さらにセグメントが語末ぴったりで切られ、区間末以降が物理的に無い。

実際、各区間を録音から `[start, end+Δ]` と少し延ばして読むと no/yes 分離は
**Δ=0:0.62 → 800ms:0.68 → 1200ms:0.70** と改善する（しかも**凍結 encoder でも**上がる）。
→ つまり 0.62 の頭打ちは **「区間末以降の情報を取れていない」こと**が主因で、encoder を変えなくても
情報を取れば上がる。

> 方針：**(a) CIF をやめて毎フレーム判定にする（好きな瞬間に・沈黙でも出せる）／
> (b) 入力を `[start, end+cap]` にして区間末以降（trailing）も観測する**。
> ＝「CIF-TEASER が取れなかった情報を、モデルが使えるようにする」。
> encoder の ASR 共有学習は CIF-TEASER と同じで、差分ではない（前提）。

## 2. 手法の全体像

```
   音声  [start, end+cap]   ← 区間末以降(trailing)も含めて入力（cap=1.2s）
              │
       共有エンコーダ
   (Contextual Block Conformer
    ・ASR と同時学習・streaming)
              │
       各フレーム encoder_out[:, t, :]
            (B, 256)   ※1 frame ≈ 33ms
              │
      ┌───────┴────────┐
      │  発話区間末検出  │   （毎フレームの no/yes/other 予測器）
      │  ヘッド (0.28M)  │
      └───────┬────────┘
              │
       Linear 256 → 128
              │
   因果 conv × 3 層
   （各時刻の特徴を「過去だけ」見て整える時間方向の畳み込み。
     dilation 1→2→4 で過去≈0.9秒まで参照 / k=5 / 残差）
              │
       Linear 128 → 3
              │
       cls_logits_t
          (B, 3)
              │
           softmax
              │
            p_t
          (B, 3)   no / yes / other
                       ◄── モデルの出力はここまで（毎フレームの確率）

  ┄┄┄┄ ここから下は「推論/評価時の使い方」（学習されない・モデル外）┄┄┄┄

   p_t を先頭から時間順に見て、十分確信できた時点でそのクラスに確定する。例：
     ・確信度 p_max が高い状態が数フレーム続いたら確定
     ・または 確からしさの差(top1−top2)が積み上がったら確定
              │
              ▼
   早く決めるほど遅延小・遅く決めるほど精度↑（精度と早さのトレードオフ）
```

> エンコーダは ASR と共有して同時学習する（CIF-TEASER と同じ前提。言語形式の表現に必要）。
> 入力は trailing 込みの `[start, end+cap]`（§1・§4-1）。損失や ASR 側の配線は §4。

### 発話区間末検出ヘッドとは（初めての人向け）

エンコーダが作る「各時刻の音声特徴（encoder_out）」を受け取り、**その時刻までの情報だけ**を使って、
**毎フレーム**「いま発話が意味的に区切れているか」を `no`（まだ続く）/`yes`（区間末）/`other`（相槌）の
3 つの確率で出す**小さなネットワーク**です（パラメータ約 0.28M）。要点は 3 つ：

- **毎フレーム出す**：33ms ごとに判定を更新する。だから「いつ十分確信できたか」を時間軸で追える（早期確定の土台）。
- **因果（未来を見ない）**：時刻 t の判定に t より後の音声を使わない畳み込みだけで作る。だから**ストリーミング**
  （リアルタイムに先頭から処理）でそのまま使える。
- **少し過去を見る**：`dilated conv`（層を重ねると遠くの過去まで効率よく見える畳み込み）を 3 層重ね、
  **過去約 0.9 秒**の文脈を使う。語尾・言い回し（「〜よね」「〜けど」等）の判断にこのくらいの幅が要る。

> まとめると：**「各時刻の音声特徴 → その時点までで no/yes/other を毎フレーム判定する小型ネット」**。
> その出力（毎フレームの確率の並び）に停止規則（§5）をかけて、確信できた瞬間に早期確定する。

CIF-TEASER との対比：

| 観点 | CIF-TEASER（旧） | 本手法（新） |
|---|---|---|
| 判定のタイミング | 単語が出るたび（区切りに縛られる） | **毎フレーム**（好きな瞬間に「いま区切れるか」を出せる） |
| 区間末以降の観測 | できない（語末切り・沈黙で発火が止まる） | **できる**（入力を `[start, end+cap]` に延長） |
| 主タスク | slave 分類 + master 停止の 2 段 | frame 分類（cls）1 本 + 時間重み |
| 早期確定 | stop_head を学習（教師が矛盾し飽和） | 確率列に停止規則を**後付け**（学習しない） |
| encoder | ASR と共有・同時学習 | ASR と共有・同時学習（**同じ＝差分ではない**） |

## 3. 設計の柱（なぜこの設計か）

CIF-TEASER との本質的な差分は **(1) 毎フレーム判定** と **(2) trailing の観測**（＝情報アクセス）。
**(3) encoder の ASR 共有学習は前提**（CIF-TEASER と同じで差分ではない）。

### 3-1.【主】CIF をやめて毎フレーム判定にする

> 判定を「単語が出るたび」ではなく**毎フレーム**にする。狙いは **「いま意味的に区切れるか」を毎時刻チェックし、
> 十分確信できた瞬間にすぐ確定する**こと。CIF は単語の区切りでしか判定できず沈黙で発火も止まるので、
> 毎時刻の連続判定にも、紛らわしい発話を直後の間で確かめることにも向かない。

毎フレーム t で確率ベクトル `p_t = softmax(cls_t)` が得られ、これが早期確定（§5）の入力＝**事後確率ストリーム**。
head は **因果畳み込みのみ**（左パディング、未来を見ない）でストリーミングと整合。受容野は dilation 1/2/4・
kernel5 で約 0.9 秒過去。

### 3-2.【主】trailing（区間末以降）を観測する

> 言語形式だけでは紛らわしい発話（例：「〜て」が文の途中か言い切りか）がある。入力を録音から
> `[start, 元区間末 + cap]`（cap=1.2s）に延長し、直後の少しの文脈を観測すると曖昧さが減る。
> 前実験の「Δ=0:0.62 → 1200ms:0.70」がこの効果を定量化したもの（§1）。

ASR が使うテキストは `[start, 元区間末]` のままなので **ASR には無害**（音声だけ伸ばす）。実装は §4-1。
注意：これは**未来の先読みではなく「待つ」こと（因果的なエンドポイント遅延）**で、推論時も同条件。

### 3-3.【前提】encoder を ASR と共有・同時学習する

> ASR（transducer）と区間末分類（cls）で encoder を共有し 1 回で同時学習する。区間末は言語的タスクなので
> encoder が文末の言語形式を表現できることは重要。**ただしこれは CIF-TEASER も同じ**（あちらも tag 損失が
> encoder に逆伝播していた）で、本手法固有の差分ではない。

> 補足：未来VA（「この先 h 秒、対象話者が話しているか」を当てる自己教師）を補助に足す案も試したが、
> 最も VAP 的で本タスクの目的（意味的完結）とズレ、学習も不安定だったため**採用しない**（§8）。

## 4. 学習方法

### 4-1. データ準備：trailing 延長（自動）

各区間の `segments`（`utt reco start end`）の **end を +cap して録音から読み直す**ディレクトリを作る。
発話内容（テキスト・ラベル）は変えず、聞く音声だけ後ろに伸ばす。

```
元区間:   [start ───────── 元end]                 ← ASR のテキストはこの範囲
延長後:   [start ───────── 元end ····· 元end+cap]  ← encoder が見る範囲（trailing 込み・cap=1.2s）
```

（`local/make_trailing_segments.py` / `local/build_trailing_datadir.sh` / 前処理ラッパー `asr_trailing.sh`）

### 4-2. 損失：ASR と区間末を同時学習（2 項）

```
L = loss_transducer  +  α · loss_tag        （α = 0.3）
```

**(a) loss_transducer**：既存の ASR（RNN-T）損失。encoder を言語表現へ引っ張る。

**(b) loss_tag（区間末・時間重み付き CE）**

区間ラベルは 1 個だが frame-level に学習させたいので、**全フレームに同じラベルを broadcast** し、
**時間重み w(t)** を掛けて平均する。

```
w(t) = floor + (1 − floor) · (t / T) ,  floor = 0.1     （t=フレーム位置, T=区間長）

loss_tag = Σ_t w(t) · CE( cls_t , label )  /  Σ_t w(t)      （クラス重みも掛けられる）
```

> **なぜ時間重みか**：序盤フレームの誤りは軽く、終盤に近づくほど重く罰する。
> 「序盤は無理に当てなくてよい・終盤は外すな」を損失で表現し、**早く決めること（遅延小）と
> 外さないこと（誤判定小）のトレードオフ**を学習に内包する。

具体例（区間長 T=6 フレーム、正解 `<yes>`）：

```
frame:        0     1     2     3     4     5
w(t):       0.10  0.28  0.46  0.64  0.82  1.00     ← 終盤ほど重い
→ frame0 で <yes> を外しても罰は軽い。frame5 で外すと重く罰される。
```

> ※今回報告した結果（§7）は、補助の未来VA損失 `β·loss_va`（β=0.2）も足した学習で得たもの。
> VA は目的とズレ不安定だったため**推奨構成からは外す**（VA なしでの再学習が次の実験。§8）。

### 4-3. クラス重み（`<no>` の底上げ）

素の学習では多数派 `<yes>` に寄り、`<no>`（まだ続く）を取りこぼす。CE にクラス重みを掛ける：

```
tag_class_weight = [w_no, w_yes, w_other] = [1.92, 1.0, 1.63]
```

> `<no>` の誤りを重く罰し、判定境界を no 側へ動かして recall を底上げする。
> （重みは**天井＝分離可能性そのもの**は上げず、誤りの**配分**を変えるレバー。評価では
>  `<no>` recall 0.42→0.58・macro-F1 0.64→0.68 と改善した。詳細は results §5。）

### 4-4. 学習の段取り

```
Stage 0  土台データ準備：asr_trailing.sh が <set>_trail（trailing 延長）を構築
Stage 1  collect stats（特徴統計）
Stage 2  本学習：encoder 共有で L = loss_transducer + α·loss_tag を最小化
         best 基準は valid.loss（ASR寄り）と valid.tag_acc（区間末）の 2 本を保存
```

## 5. 推論：停止規則による早期確定

学習した cls の**毎フレーム確率ストリーム** `p_t` に、停止規則を**事後適用**する（モデル外・学習しない）。

### 5-1. TEASER（確信度ベース）

```
p_max,t = max_c p_t[c] が θ を超え、かつ argmax クラスが v フレーム連続 → その時点で確定
発火しなければ最終フレームで確定（=最遅・全部待つ）
```

### 5-2. SPRT（証拠累積ベース）

```
累積 acc_c += log p_t[c] ;  (最大 − 2番目) > bound → 確定
```

> 言語形式から意味的完結が明確な発話は数フレームで境界を超えて**即確定**、曖昧な発話は
> 追加の言語文脈（や少しの trailing）で確信が立つまで**自然に待つ**。これが「易しいものは早く・
> 難しいものは待つ」の実体。θ や bound を上げるほど **精度↑・確定位置（遅延）↑** の動作曲線が得られる。

実測でも θ/bound を上げる（=待つ）ほど `<no>`（まだ続く）の recall が単調改善した
（曖昧な「継続」は少し待つと確信が立つ、という挙動）。

### 5-3. 早期分類としての位置づけ（学習ロジックの分類）

本タスクは「**系列の早期分類**（accuracy–latency トレードオフ）」という確立した問題クラスで、
時系列の早期分類（ECTS/EARLIEST）・逐次仮説検定（SPRT）・適応計算時間・同時通訳・
ニューラルエンドポインティング等が兄弟問題（詳細 [turntaking_related_problems.md](turntaking_related_problems.md)）。
学習ロジックは 3 系統に整理でき、本手法の現状と「忠実な次の一手」は：

| 系統 | 中身 | 本手法 |
|---|---|---|
| ① 後付けしきい値 | 各時刻分類器＋推論時に停止規則（TEASER/SPRT） | **採用**（§5-1,5-2） |
| ③ 時間重み prefix 教師 | 全時刻に最終ラベル＋終盤ほど重い罰 | **採用**（§4-2b） |
| ② 学習型停止方策 | 「停止/継続」を出し、損失に**遅延罰＋早すぎ誤判定罰**を明示（RL等） | 未採用＝**次の一手** |

> ②（学習型 halting 方策）は「遅延ペナルティ＋早すぎ誤判定ペナルティを損失に明示する」という
> 当初の定式化に最も忠実な形（status_overview の手法D／文献の EARLIEST・ACT 系）。現状は ③＋① で近似している。

## 6. ハイパーパラメータと評価方法

- 学習：α(turntaking_weight)=0.3, floor=0.1, クラス重み=[1.92,1.0,1.63], cap=1.2s。
  （報告した結果は補助の va_weight=0.2 込み。推奨構成では VA を外す。）
- 停止規則の θ（TEASER）/ bound（SPRT）は**学習せず dev で sweep**し、本番は eval で 1 回評価。
- 指標：accuracy・クラス別 recall/F1・macro-F1 に加え、no/yes 二値分離（methodA 比較軸）と
  「**確定位置%**（発話のどこで止めたか）」＝早期性。

> **dev（開発セット）とは**：学習・テストと別のチューニング専用データ（ここでは train_dev_trail）。
> テストで閾値を選ぶと過剰適合するので、dev で選んだ設定を eval で 1 回だけ測る（TEASER と同じ作法）。

## 7. 結果の要点（詳細は results §3,§5）

- **no/yes 二値分離 0.717**（重みなし）/ **0.706**（重み版）＝ **methodA の 0.62 を突破**し、診断の ~0.70 を維持。
  → 効いたのは **frame-level＋trailing（CIFでは取れなかった情報アクセス）**。encoder 共有は CIF-TEASER と同じで差分ではない。
- クラス重み版は `<no>` recall 0.42→0.58・macro-F1 0.64→0.68 と**バランス改善**（yes recall は低下）。
- 早期確定は θ/bound で「精度 × 確定位置%」の動作曲線が得られ、用途に応じて運用点を選べる。
- ※これらは未来VA（β=0.2）込みの学習で得た数値。VA を外した再学習で取り直すのが次の一手（§8）。

## 8. 一言まとめ と 次の一手

> **意味的発話区間末（≠VAP shift/hold）の早期分類**を解く。CIF-TEASER との本質的な差分は
> **(1) 毎フレーム判定にして（沈黙でも・好きな瞬間に出せる）、(2) 入力を `[start, end+cap]` にして
> 区間末以降（trailing）も観測する**こと＝CIF では取れなかった情報を使えるようにした点。encoder の ASR 共有学習は
> CIF-TEASER と同じ前提。早期確定はモデル外で、frame 確率列への停止規則の事後適用で行う。これで 0.62 の頭打ちを
> 解消し、精度×早期性を運用時に選べる形にした。
