# Method A (CIF-TEASER) 診断と改善方針

作成日: 2026-06-12
対象: `egs2/cejc/asr1` / `cif-teaser-methodA-v2`（Stage1 / Stage2 / dev sweep / 推論）

タグ定義: `0=<no>`, `1=<yes>`, `2=<other>`

---

## 0. 結論（要約）

学習が機能していない原因は **2 か所**あり、両者は連鎖している。

1. **【根本原因 / Stage1】** `tag_classifier` が `<no>` と `<yes>` を分離できない。
   原因は重み調整ではなく **構造的制約**：分類器が「単一 fire の 256 次元 CIF 表現」だけを
   独立に見ており、`<no>/<yes>` の区別に必要な**発話文脈・履歴**を持たない。
   クラス重みを入れても動作点が滑るだけで識別力（macro F1）は上がらない。

2. **【連鎖した破綻 / Stage2】** `stop_head` の学習信号（`stop_target`）が
   「分類が正しいか（＝隠れ正解 y に依存）」で定義されているのに、入力特徴 φ には y を
   判定できる情報が無い。**同じ見た目の φ に正解/不正解で真逆のラベル**が付くため、
   head は周辺分布しか学べず `stop_acc` が早期に天井（≈0.76）へ張り付く。

dev sweep の「`threshold=0.3`（最低値）が最良」は調整の成功ではなく、
**stop_prob のダイナミックレンジが死んでいる**ことの症状である。

## 2. Stage 1：tag_classifier が `<no>/<yes>` を分離できない

### 証拠
- `train.log` の valid `tag_acc` は epoch 118→120 で **0.74〜0.76 で頭打ち**、`loss_tag` も 0.74 前後で停滞。学習後半は改善していない。
- v2（クラス重み `[1.92, 1.00, 1.63]` 導入後）の混同行列（dev, thr0.3,v1）:

  ```
              予測→  <no>   <yes>  <other>
  正解<no>            769    1521     90     ← recall 0.323、大半が <yes> へ
  正解<yes>          1023    6512    285
  正解<other>          83     282    3465     ← recall 0.905
  ```
- クラス重み導入で `<no>`→`<yes>` 流出（旧 72.6%）は減ったが、今度は `<yes>`→`<no>` が増加。
  **境界が滑っただけで macro F1 は 0.69 のまま。**

### 構造的原因（コード）
`espnet2/asr/espnet_model_cif_tag.py:153`

```python
self.tag_classifier = nn.Sequential(
    nn.Linear(enc_dim, 128),   # enc_dim = 256
    nn.ReLU(),
    nn.Linear(128, num_tag_classes),   # 3
)
```

これを `cif_out`（B, T_cif, 256）の **各 fire に独立適用**（`espnet_model_cif_tag.py:309`）。
fire 同士は互いを参照しない。

- `<other>`: 語彙的に明確 → 単一 fire で分離可能（F1 0.93）。
- `<no>` / `<yes>`: 発話全体の文脈・履歴に依存 → 単一 fire 表現では情報不足。
  分類器は **Bayes 限界**に張り付いており、重み調整では解けない。

## 3. Stage 2：stop_head が天井に張り付いて学習しない

### 証拠（`train.log`）
| epoch | 1 | 4 | 6 | 8 | … | 50 |
|---|---|---|---|---|---|---|
| train stop_acc | 0.667 | 0.749 | 0.756 | 0.756 | (平坦) | 0.760 |
| valid stop_acc | — | 0.760 | 0.767 | 0.774 | (平坦) | ~0.77 |
| loss_stop | 0.452 | 0.310 | 0.307 | 0.307 | (平坦) | 0.347 |
| grad_norm | — | — | — | — | — | 0.32 |

- **epoch 6〜8 で収束、残り 42 epoch は無駄**。grad_norm 0.32 と極小。
- `pos_ratio ≈ 0.65`（train）/ `0.71`（valid）：stop_target の 65〜71% が「stop=1」。
- `valid.loss.best.pth` は最終 50epoch を指す＝**実質ベスト選択が効いていない**。

### 構造的原因（コード）
`stop_target` 生成 `espnet2/asr/espnet_model_cif_teaser.py:311` `_make_stop_targets`:

```
τ* = 「そこ以降すべての fire で argmax が正解」になる最初の fire
stop_target[i] = 1 if i ≥ τ*   （正解が一度も無ければ最終 fire のみ 1）
```

→ **stop_target は「正解か（隠れ y に依存）」で定義される。**

一方 stop_head の入力 φ_i（`_build_phi`, 22 次元）は
`[sort(p_i), margin, entropy, position, cif_proj(16)]` で **y を含まない**。

結果:
- 自信満々で外す `<no>` の fire と、自信満々で当てる `<yes>` の fire は **φ 上ほぼ同一**なのに
  target は 0 と 1。→ 矛盾した教師信号。
- head が学べるのは「`<other>`っぽさ＝自信」相関のみ。だから `<other>` は正確に確定し、
  `<no>/<yes>` は当てずっぽうで早期確定する（クラス別 earliness: other 0.80, yes 0.32, no 0.39）。
- pos_ratio が高く「基本止まれ」に偏る → stop_prob が狭帯域に圧縮。

## 4. dev sweep：「thr=0.3 が最良」は症状

- stop_prob のダイナミックレンジが死んでいるため、**最低閾値 0.3 だけが早期停止を通す**。
  高閾値は全員を最後まで遅延（報告された HM 0.062 と整合）。
- HM=0.632 の中身も `<other>`（acc0.92, earliness0.80）と「早いが外す `<no>/<yes>`」の水増し。
- **dev/test 乖離**：`<no>` recall は dev 0.323 → test 0.599、HM は dev 0.632 → test 0.580。
  動作点 (thr0.3,v1) が dev に過適合し test へ転移していない兆候。

---

## 5. 推論：因果的に 1 fire ずつ処理し、文脈を持たない

`inference_tag_teaser`（`espnet_model_cif_teaser.py:401`）は
`for i in range(n_fires)` で **1 fire ずつ因果的に**処理し、各 fire で
`tag_classifier(cif_out[b,i])` を独立に評価する。

- 早期確定（未来を見ない）パラダイムとしては正しい。
- しかし各 fire の判断に**過去 fire の履歴が一切入らない**ため、Stage1 の構造的制約が
  そのまま推論時の `<no>/<yes>` 誤りに直結する。
- 改善で時間文脈を足す場合も、**因果性（過去のみ参照）を必ず保つ**こと。

---

## 6. 改善方針（C → A）

### 方針 A（本命）: 因果的時間文脈の追加
`tag_classifier` の前に **causal な再帰層（GRU/LSTM 1 層）** を挟み、各 fire が
**過去の fire 履歴**を見てから分類する。

- fire 系列 `cif_out`（B, T_cif, 256）に causal GRU を適用 → 各 fire の隠れ状態で分類。
- 推論ループでは GRU の hidden state を fire ごとに繰り越す（因果性を自然に保てる）。
- `<no>/<yes>` の文脈依存を直接解消することを狙う。
- コスト: **Stage1 全再学習** ＋ 推論パス修正。Stage2 はその後やり直し。

### 方針 C（先に実施・安全策）: 分離可能性の診断
A で長時間の再学習に入る前に、**文脈を足せば本当に分離できるのか**を軽量に検証する。

1. 学習済み Stage1 で dev/test の `cif_out` を抽出。
2. `<no>` vs `<yes>` の 2 クラスについて:
   - (a) 単一 fire 表現での線形プローブ精度（現状の上限の確認）。
   - (b) 発話内 fire を平均/最終/履歴連結した表現での線形プローブ精度。
   - (a) ≪ (b) なら「文脈を足せば分離可能」＝ A に進む価値あり。
   - (a) ≈ (b) で両方低いなら、cif_out 自体に情報が無い → 上流（encoder 出力や
     decoder/テキスト文脈）の活用、またはラベル定義の見直しを検討。
3. 併せて `<no>/<yes>` ラベルの素性（発話長・話者・文脈）に偏りが無いか軽く確認。

### 進め方
**C（診断）→ 結果次第で A（causal GRU 実装 + Stage1 再学習）** の順で進める。
C の結果が出た時点で A の具体設計（GRU 次元・層数・損失）を確定する。

---

## 7. 【C 診断の結果（2026-06-12）】方針 A は棄却

`local/diagnose_noyes_separability.py` で dev（no/yes 各 2,380 発話、計 63,979 fire）から
cif_out を抽出し、`<no>` vs `<yes>` を線形プローブ（balanced, 発話単位 split, chance=0.5）。

| 表現 | balanced acc | macro F1 |
|---|---|---|
| (1) per-fire 単一 | **0.621** | 0.621 |
| (2) per-fire 因果累積平均 | 0.602（Δ −0.019）| 0.602 |
| (3) 発話 最終 fire | 0.623 | 0.623 |
| (4) 発話 全 fire 平均 | 0.614（Δ −0.010）| 0.614 |

### 判明したこと
- cif_out は no/yes 情報を**弱くしか持たない**（線形 0.62、nonlinear 現分類器も同等）。
- **文脈集約（causal-mean / 全平均）は改善しない**（むしろ悪化）。
  → 「単一 fire だから分からない」という仮説は**棄却**。**causal GRU（方針 A）では解けない見込み**。

### 真のボトルネック（更新後の理解）
時間文脈の欠如ではなく、**cif_out（CIF 音響サマリ）自体に no/yes の弁別情報が乏しい**。
no/yes は音響だけでは決まらず、**語彙・意味（実際に何と言ったか）に依存**する可能性が高い。

### 次の方針（A に代えて）
1. **上流/語彙情報のプローブ**：encoder_out（CIF 前）や Decoder/テキスト表現から
   no/yes が分離可能かを確認。テキストで分離できるなら、tag_classifier に
   **語彙・Decoder 情報を合流**させる設計に変更する。
2. **ラベル定義の確認**：no/yes が音響で決まる量なのか、そもそも曖昧でないかをドメイン側で確認。

→ A（GRU 再学習）には進まず、まず 1 の上流プローブを実施する。

## 8. 【C-2 診断の結果（2026-06-12）】encoder_out でも分離できない

ラベル定義が判明: `<no>`=区間末でない, `<yes>`=区間末である, `<other>`=相槌。
**＝発話区間末（エンドポイント）検出**。韻律と文脈に依存するタスク。

`local/diagnose_encoder_vs_cif.py` で各表現の no/yes 線形プローブ（balanced, chance=0.5）:

| 表現 | bal_acc |
|---|---|
| cif_last | 0.623 |
| cif_mean | 0.614 |
| enc_mean | 0.608 |
| enc_last | 0.606 |
| enc_lastk（末尾10フレーム平均）| 0.617 |
| enc_max | 0.599 |
| cif_last + enc_lastk（結合）| 0.592 |
| enc_lastk [MLP] | 0.609 |

**全表現が 0.60〜0.62 に張り付く。encoder_out は cif_out より良くない。MLP でも結合でも伸びない。**

区間長の分布（utt-id 時間範囲）:

| ラベル | n | 中央値 | 平均 |
|---|---|---|---|
| `<no>` 非区間末 | 2,380 | 1,500 | 2,021 |
| `<yes>` 区間末 | 7,820 | 1,380 | 1,723 |
| `<other>` 相槌 | 3,839 | 385 | 472 |

→ `<other>` は極端に短く長さだけで分離可能（精度 0.92 の理由）。
   `<no>`/`<yes>` は長さ分布がほぼ重なり、長さでも分離できない。

### 確定した結論
- **この発話セグメント内の音響特徴は、no/yes(エンドポイント) を ~0.62 までしか分離できない**
  （cif/encoder/線形/非線形いずれも同じ天井）。現分類器（test no-F1 0.55）は既にほぼこの天井。
- **CIF 圧縮が原因ではない**。再表現（GRU 含む）では改善しない。
- エンドポイント判定の最強手がかり（**発話直後の無音・次話者ターン・会話文脈**）は
  **現在のモデルが見ているセグメントの外**にある可能性が高い。

### 制約（2026-06-12 確認）
- Encoder は **contextual block conformer（ストリーミング ASR）**。
  **未来文脈は使用禁止、過去文脈は可**。
- → 「後続情報の活用（窓延長 / look_ahead 拡大）」は**棄却**（未来参照のため）。

### データ確認（末尾無音, dev 各400発話）
| ラベル | 区間長 中央値 | 末尾無音 中央値 | 無音>100ms 割合 |
|---|---|---|---|
| `<no>` 非区間末 | 1,438ms | 0ms | 9% |
| `<yes>` 区間末 | 1,312ms | 0ms | 10% |
| `<other>` 相槌 | 366ms | 0ms | 3% |

→ **セグメントは語末でぶつ切り**（末尾無音ほぼ 0ms）。区間末の最強手がかり
   「発話直後の無音」はデータから除去済み、かつ未来なので**二重に使えない**。

### 確定した改善の方向（streaming 制約下）
再表現系（A〜C）と後続情報は棄却。**因果的に使える新情報＝過去文脈のみ**:
1. **過去の会話文脈（最有力）**：会話セッション内の時系列を再構成可能
   （`T005_001`=会話, `IC01..`=話者, timestamp 共通クロック）。
   自分の過去発話＋相手の先行発話を入力に加え、統語・意味的な区間末予測を補う。
2. **因果的韻律**：語末までの F0 下降・語末伸長など終端を予測する手がかり。
   ただし encoder が既に音響を符号化し 0.62 で頭打ち → 上積みは限定的の可能性。

### 次の検証（C-3, 予定）
過去文脈レバーの事前検証：各対象区間に対し、同一会話の直前区間（自話者/相手）の
表現を結合し、no/yes 線形プローブが 0.62 を超えるかを確認してから設計を確定する。

### 戦略的論点（要議論）
- streaming + 区間末検出は本質的に困難（末を当てる最強手がかり＝直後の無音が未来＝禁止）。
  因果的上限 0.62 はこの構造的限界を反映。過去文脈で上積みできても天井は高くない可能性。
- TEASER の「早期確定」と「区間末検出」の整合性、タスク枠組み自体の再検討も論点。

## 9. 【C-3 診断の結果（2026-06-12）】過去文脈も効かない

`local/diagnose_context_probe.py`：同一会話の時系列を再構成し、対象区間に直前区間
（自話者/相手/誰でも）の cif_mean と gap を結合して no/yes 線形プローブ。

| 表現 | bal_acc |
|---|---|
| cur のみ（baseline）| 0.623 |
| cur + own_prev（自話者直前）| 0.603 |
| cur + intloc_prev（相手直前）| 0.601 |
| cur + any_prev（直前誰でも）| 0.593 |
| cur + own + intloc + gaps | 0.570 |

→ **過去文脈はすべて改善せず、むしろ悪化**（Δ −0.021〜−0.053）。
   frozen 特徴＋線形プローブだが、悪化は「直前区間の音響サマリが no/yes を線形に予測しない」ことを示す。

## 10. 総合結論：encoder 側レバーは出尽くし

| 検証 | レバー | 結果 |
|---|---|---|
| C | 時間文脈集約（GRU 相当）| 効かず |
| C-2 | encoder_out / 非線形 / 結合 | 0.62 頭打ち |
| データ | 末尾無音 | 0ms（ぶつ切り）|
| C-3 | 過去会話文脈（自/相手）| 効かず（悪化）|

**streaming（未来禁止）制約下では、no/yes(区間末) は ~0.62 が構造的上限。** 区間末の決定打
（直後の無音・次ターン）が未来＝禁止であることが根本原因。encoder 表現・文脈の工夫では破れない。

### 残された選択肢（戦略判断）
1. **streaming 制約の最小緩和**：区間末直後に**有界の look-ahead（例 200-300ms）**を許し、
   末尾の無音/間を観測する。天井を破る最有力だが streaming 要件とトレードオフ。
2. **セグメント化/ラベルの再検討**：語末ぶつ切りで区間末手がかりが消えている。
   末尾に文脈を含む再分割、またはラベル定義の見直し。
3. **テキスト/統語文脈（未検証レバー）**：デコード文字列の統語的完結性（「…です。」vs「…で、」）。
   ただし encoder は ASR 共学習で語彙も符号化済みかつ 0.62 頭打ちのため、上積みの prior は中〜低。
4. **枠組みの再検討**：区間末検出を TEASER 早期確定で解く設定自体の妥当性。
   現状の `<other>`（相槌, F1 0.93）は機能、no/yes は構造的に頭打ちと割り切る。

→ encoder 側の再学習（v3）は現時点で正当化されない。上記 1〜4 の戦略判断が先。
