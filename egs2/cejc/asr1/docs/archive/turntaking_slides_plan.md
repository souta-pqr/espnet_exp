# 発表スライド改訂プラン（各スライドの書き方）

作成日: 2026-06-16
対象: 研究紹介スライド「発話区間末検出ラベルを利用した音声認識」（M2 小堀）の改訂
関連: [turntaking_multitask_method.md](turntaking_multitask_method.md) / [turntaking_related_problems.md](turntaking_related_problems.md) / [methodA_teaser_why_failed.md](methodA_teaser_why_failed.md)

> 教授コメントへの対応方針（最重要 3 点）:
> 1. **「発話区間末」の独自の意味**（音響的終端でも・ターン交替予測でもない＝**意味的完結**）が伝わる背景・目的にする。
> 2. 図は**モデル図**にする（プログラムのフローチャート＝大きな◇分岐 をやめる）。
> 3. 出力名は「タグ確率」ではなく **「発話区間末タグ確率（no/yes/other）」** と完全名で書く。
>
> 全体ストーリー: 背景・目的 → **第一アプローチ CIF** → **CIF の限界（`<no>` が予測できない）** →
> **現アプローチ frame-level＋trailing で改善** → 早期確定ロジック → データ。

---

## 共通ルール（全スライド）
- 出力は必ず **「発話区間末タグ確率（no/yes/other）」**。「タグ確率」単独は禁止。
- 「発話区間末」は §3 の定義以外の意味で使わない（**音響的な無音終端 / ターン交替予測と混ぜない**）。
- 図は「上→下にデータが流れ、箱＝層/モジュール、矢印に流れるもの（次元）」。**◇Yes/No の大分岐は使わない**（停止条件は小さな注記にする）。

---

## スライド 1：タイトル
- タイトル：発話区間末検出ラベルを利用した音声認識
- **副題を追加**（独自定義の予告）：「— ストリーミング音声認識における**意味的発話区間末**の早期検出 —」

---

## スライド 2：背景
**狙い**：ASR に加えて「意味的発話区間末検出」という新タスクを定義し、なぜ必要かを示す。
- 本文（箇条書き）:
  - ASR：「**何を言ったか**」を出力（従来）。
  - 本研究が加えるもの：**話者がいま“意味的に”ひとつの発話を言い終えたか**を判定する発話区間末検出。
  - なぜ必要か（対話システム動機）：相手が言い終えたか分からないと**割り込み／応答遅延**が起きる。
    **単なる無音待ち（VAD）では「ポーズはあるが続く」「短い無音で終わる」を取り違える** → だから**意味で**判定したい。
- **囲み枠で“区別”を明示（教授指摘の本丸）**:
  ```
  本研究の「発話区間末」とは
    = 話者が “意味的に” ひとつの発話を言い終えた位置
    ・音響的な無音検出(VAD) ではない
    ・次に誰が話すか(ターン交替予測) でもない
  ```
- 現スライドの「話者B：まだ聞いたほうがいいな」吹き出しは**応用例として残す**。ただし
  「これは応用で、**モデルが直接予測するのは話者Aの意味的区間末**」と一言添える（混同防止）。

---

## スライド 3：発話区間末タグの定義（新規・最重要）
**狙い**：3 クラスを**具体例**で定義し、「音響でなく言語（意味）で決める」を伝える。
- 3 クラス表＋例:
  ```
  <yes>  意味的発話区間末（言い終えた）
     例: 「〜だと思うよ」「行けないです」「どこ置いたかな(独り言)」「いいの?(問いかけ)」
  <no>   まだ区間末でない（意味的に続く）
     例: 「今日さー」「〜なんだけど」「〜て,」「えーと(フィラー)」「行け…(言いかけ)」
  <other> 相槌   例: 「うん」「へぇ」
  ```
- 一言：**手がかりの主役は“文末の言語形式（言葉）”**。
  「〜よね／〜かな／言い切り」＝yes 寄り、「〜て／〜けど／中止形・フィラー」＝no。
  （テキストのみの LLM で約 8 割当たる、という事実が「言語形式が主役」を裏づける。）

---

## スライド 4：目的
- 本文:
  - **発話区間末検出付き ASR モデル**を作る（ASR と統合）。
  - ストリーミングで**できるだけ早く・誤検出なく**「意味的発話区間末」を確定したい。
  - ＝ **精度（誤検出しない）と 早さ（earliness）の両立**。
- 図（現行の「誤検出／理想／遅い」を流用・良い）:
  ```
              誤検出        理想        遅い
  話者A: [えーと, 明日なんですけど都合が悪くて行けないです]──► t
  ```
  - `t` 軸＝時間（ストリーミングで先頭から処理）と明記。
- 締め：「**理想のタイミングで確定するにはどうするか**」→ 以降につなぐ。

## スライド 5：第一アプローチ（CIF モデル）
- タイトル下に **「最初に試したアプローチ」** と明記。
- モデル図（モデル図として／出力名修正）:
  ```
            音声
             │
        Encoder（Contextual Block Transformer）
             │
          CIF 機構
        ┌────┴─────┐
        ▼          ▼
     Decoder   tag_classifier（MLP: D→128→C）
     → テキスト  → 発話区間末タグ確率（no/yes/other）   ← 「タグ確率」を修正
  ```
- 右に小さく「早期確定ロジックをどうするか」→ 後半への伏線（赤枠は tag_classifier 側）。

## スライド 6：CIF 機構
- 現行のまま（A=重み α / C=累積 / T=発火 の図、出典 [1] 明記）でよい。
- 一言：CIF は**音響をトークン単位の発火に積算**する機構（＝**語に同期**して発火）。
  → この「語に同期」が次スライドの限界に効く、と前振りしておく。

---

## スライド 7：CIF アプローチの限界（`<no>` が予測できない）★新規
**狙い**：第一アプローチの失敗とその**理由**を示し、現アプローチへ橋渡し。
- 結果:
  - `<other>`（相槌）は解ける（F1 ≈ 0.93）。
  - **しかし `<no>`（発話区間末でない）の recall は約 0.24**、**その約 7 割が `<yes>` に誤判定**。
    → no/yes の分離が **0.62 で頭打ち**。
- 理由（**表現力ではなく情報不足**）:
  - `<no>`（まだ続く）の決め手は**区間末以降**（このあと無音か／本人が話し続けるか）にある。
  - だが CIF は **沈黙では発火しない**（最終語で発火が尽きる）＋ セグメントが **語末ぴったり**で切られる。
    → **区間末以降を観測できない**。
- 図:
  ```
  発話:   … 行け ない です ［区間末］──── 無音 / 本人が続ける? ────
  CIF発火:  ●    ●    ●    ●          ↑ ここを観測できない（発火が尽きる）
            （語に同期して発火するため、区間末以降に手がかりが残らない）
  ```
- 締め：「**“まだ続くか”の情報が入力に入っていない** → だから `<no>` が当たらない」。

---

## スライド 8：現在のアプローチ（frame-level ＋ trailing）★新規
**狙い**：限界の原因（区間末以降を観測できない）を**直す**2 つの変更を示す。
- 変更点は 2 つ:
  1. **CIF をやめて毎フレーム判定**：沈黙でも出力でき、「いま区切れるか」を毎時刻チェックできる。
  2. **入力を `[start, end+Δ]` に延長**し、**区間末以降（trailing）も観測**：録音の続きを少し聞く
     （＝未来の盗み見ではなく**因果的な「待ち」**）。これで「本人が続けるか／無音か」が分かる。
  - 補足 1 行：encoder は ASR と共有・同時学習（**ここは CIF 時と同じ前提**。変えたのは上の 2 点）。
- **なぜ改善するか**：`<no>` の決め手（区間末以降に本人が続けている）を**観測できるようになる**から。
- モデル図（frame-level 版）:
  ```
        音声  [start, end+Δ]   ← 区間末以降も入力（trailing）
              │
        共有エンコーダ（ASR と同時学習）
              │ 各フレームの特徴
      ┌───────┴────────┐
      ▼                ▼
   Decoder        発話区間末検出ヘッド
   → テキスト       → 発話区間末タグ確率（毎フレーム no/yes/other）
  ```
- 改善結果（提示すると強い）:
  - no/yes 二値分離 **0.62 → 0.71**
  - `<no>` recall **0.24 → 0.58**（クラス重み導入時）
  - 前実験（区間末以降を Δ 延ばすほど上がる）：**Δ=0:0.62 → 800ms:0.68 → 1200ms:0.70**

## スライド 10–13：各早期確定手法（モデル図化）
**共通方針**（フローチャート → モデル図）:
- **大きな◇分岐（Yes/No）をやめる**。学習対象のモジュールを**箱**で積み、停止条件は**小さな注記 1 行**に。
- 入力は **「毎フレームの発話区間末タグ確率 p_t」**（旧「fire / CIF 出力」→「フレーム」）。

- **10. TEASER**:
  ```
  p_t → [ 停止判定器 stop_head (MLP) ] → stop_prob
  （注記）stop_prob>θ が 同じクラスで v フレーム連続 → 確定
  ```
- **11. ECONOMY**:
  ```
  p_t → [ 期待コスト計算 ] → 確定
  （右に式）L = C_mis[y,ŷ] + α·t/(T−1) ／ E[L|t] を比較し最小で確定
  ```
- **12. SPRT**:
  ```
  p_t → [ LLR を累積 ] → 確定
  （右に式）Λ_k(t)=Σ_{j≤t} log p(k|x_j)/max_{k'≠k} p(k'|x_j)；最大>閾値で確定
  ```
- **13. RL halting**:
  ```
  p_t, 状態 h_t → [ Controller (MLP・強化学習) ] → halt_prob
  （注記）halt_prob>θ → 確定／else 次フレーム
  （右に式）報酬 R = r_correct(ŷ_τ,y) − λ·τ/(T−1)
  ```
- 各図の下に**小さく 1 行**「条件成立→確定／不成立→次フレーム」。

## スライド 14：データ作成
- 現行（CEJC・3 クラス表・LLM 調査中）でよい。+1 行:
  - **タグは区間単位で付与（基準＝文末の言語形式）。LLM での自動付与を調査中。**

## 付録：数値の出どころ（引用時の注意）
- `<no>` recall 0.24 ／ no/yes 0.62：**CIF-TEASER の診断（methodA）**。
- no/yes 0.71 ／ `<no>` recall 0.58：**現アプローチ（frame-level）の eval**（クラス重みあり）。
- 前実験 0.62→0.68→0.70：**trailing 診断（凍結 encoder の線形プローブ）**。
- 注意：現アプローチの数値は**未来VA 込みの学習で測ったもの**。確定値にするには VA なしで取り直し中
  （発表では傾向として提示で十分）。

## 付録：図の原則（再掲）
1. モデル図＝上→下にデータが流れ、箱＝層/モジュール、矢印に「流れるもの（次元）」を書く。
2. プログラムの分岐（◇Yes/No）は使わない。停止条件は小さな注記に。
3. 出力は必ず「発話区間末タグ確率（no/yes/other）」。
4. 「発話区間末」は定義（意味的完結）以外の意味で使わない。
